# Handover — bare-refgen TSDoc constructor-placement fix, published rollout, regression backlog

Written 2026-08-05, end of session. This is a working note for whoever picks this up next — not
site content. Delete it (and `regression-findings-2026-08-05.md` in this same directory) once the
outstanding work below is resolved and before this branch merges.

## 1. How this started

The user pointed at a review comment on a generated upstream doc PR:
[holepunchto/bare-url#20, discussion_r3622517981](https://github.com/holepunchto/bare-url/pull/20#discussion_r3622517981) —
a one-word "Init?" from reviewer tony-go on a spliced-in TSDoc comment.

**Root cause diagnosed:** Bare's `.d.ts` files declare a stateful export as `interface Foo {}`
(instance members) merged with `declare class Foo { constructor(...) }` (the constructor, in a
separate declaration). The TSDoc-emitting tool's manifest entry for "how to construct a `Foo`" is
keyed by the bare class name (`Foo`), and the old code let *any* container-level declaration
(interface, class, or namespace sharing that name) claim that key — on a first-come basis, in file
order. Since Bare always declares the interface before the class in every one of these files, the
constructor's doc always landed on the interface (which has no constructor), leaving a `@param`
referencing a parameter that doesn't exist on the annotated declaration.

## 5. Regression-check workflow (for re-running / widening scope)

Script is saved at
`~/.claude/projects/-Users-lucas-Documents-tether-openApi-pear-docs/400932ac-0347-4982-8a8d-e57d739723f5/workflows/scripts/bare-docs-regression-check-wf_12a4fba2-9d2.js`
on this machine (session-local — may not exist for a different agent/environment). It's reproduced
here so it can be recreated from scratch if needed. To widen it to the 29 brand-new modules
(checking for silently-missing symbols against their actual `.d.ts`, since there's no old page to
diff against), swap the compare step's approach — compare the rendered MDX against the module's
`generated/bare-refs/<name>/api-model.json` members list instead of an old page.

```js
export const meta = {
  name: 'bare-docs-regression-check',
  description: 'Compare old published bare-* module pages against their new PR-326-generated replacements for lost information',
  phases: [
    { title: 'Compare', detail: 'diff old vs new content per module batch' },
    { title: 'Verify', detail: 'adversarially confirm each flagged regression is real' },
  ],
}

const REPO = '/Users/lucas/Documents/tether/openApi/pear-docs'

// The 28 modules whose published content was REPLACED (not newly added) by this PR.
const BATCHES = [
  ['bare-apk', 'bare-atomics', 'bare-channel', 'bare-console'],
  ['bare-crypto', 'bare-fetch', 'bare-form-data', 'bare-fs'],
  ['bare-inspector', 'bare-ipc', 'bare-make', 'bare-mime'],
  ['bare-module', 'bare-os', 'bare-pipe', 'bare-posix'],
  ['bare-rpc', 'bare-sdl', 'bare-semver', 'bare-sidecar'],
  ['bare-sqlite', 'bare-stream', 'bare-subprocess', 'bare-tcp'],
  ['bare-timers', 'bare-tls', 'bare-url', 'bare-broadcast-channel'],
]

const COMPARE_SCHEMA = {
  type: 'object',
  properties: {
    modules: {
      type: 'array',
      items: {
        type: 'object',
        properties: {
          name: { type: 'string' },
          regressions: {
            type: 'array',
            items: {
              type: 'object',
              properties: {
                claim: { type: 'string', description: 'The specific fact/example/caveat present in the OLD page' },
                oldQuote: { type: 'string', description: 'Exact or near-exact quote from the old page' },
                whyMissing: { type: 'string', description: 'Why this is genuinely absent from the new page, not just reworded/moved' },
              },
              required: ['claim', 'oldQuote', 'whyMissing'],
            },
          },
        },
        required: ['name', 'regressions'],
      },
    },
  },
  required: ['modules'],
}

const VERDICT_SCHEMA = {
  type: 'object',
  properties: {
    real: { type: 'boolean', description: 'true only if this is a genuine, user-facing loss of information worth restoring' },
    reasoning: { type: 'string' },
  },
  required: ['real', 'reasoning'],
}

function comparePrompt(names) {
  return `Working directory: ${REPO} (already on the right branch — do not switch branches).

For each of these bare-* modules, compare the OLD published version of its reference page against the NEW version now in the working tree, looking SPECIFICALLY for information that existed in the OLD page and is genuinely missing from the NEW one:

${names.map((n) => `- ${n}`).join('\n')}

For module <name>:
1. Run: git show origin/published:content/reference/bare/modules/<name>.mdx   (the OLD version — if this errors, treat as no prior page, skip it, report empty regressions)
2. Read the NEW version at content/reference/bare/modules/<name>.mdx in the working tree.
3. Compare them. Flag ONLY genuine content regressions: a specific fact, worked example, platform/OS caveat, security/gotcha note, error condition, or usage detail that appears in the OLD page's prose and does NOT appear anywhere in the NEW page (not even reworded or moved to a different section/table).

Do NOT flag:
- Different overall structure, heading style, or table formatting (the new pipeline renders differently by design — that's expected, not a regression).
- A shorter intro sentence, as long as the underlying fact still appears somewhere in the new page's API section.
- Missing GitHub source-line links (removed intentionally repo-wide, out of scope).
- Missing per-symbol "Systems" platform-support badges in the API section (that's a catalog-page-level concern, not this page).

Be skeptical and conservative — only report something you can point to with an exact quote from the OLD page that has no counterpart in the NEW page. If a module has no old page (brand new), or the new page is a strict superset, report an empty regressions array for it.

Call the structured output tool with one entry per module listed above.`
}

phase('Compare')
const compareResults = await pipeline(
  BATCHES,
  (batch) => agent(comparePrompt(batch), { phase: 'Compare', schema: COMPARE_SCHEMA, label: `compare:${batch[0]}..` })
)

const allFlags = []
for (const result of compareResults) {
  if (!result) continue
  for (const mod of result.modules ?? []) {
    for (const r of mod.regressions ?? []) {
      allFlags.push({ module: mod.name, ...r })
    }
  }
}

log(`${allFlags.length} candidate regression(s) found across ${BATCHES.flat().length} modules — verifying each`)

if (allFlags.length === 0) {
  return { flagged: 0, confirmed: [] }
}

phase('Verify')
const verified = await parallel(
  allFlags.map((f) => () =>
    agent(
      `Working directory: ${REPO}. A comparison pass flagged this as content missing from the NEW version of the "${f.module}" bare module reference page (content/reference/bare/modules/${f.module}.mdx), compared to its OLD published version (git show origin/published:content/reference/bare/modules/${f.module}.mdx):

Claim: ${f.claim}
Old quote: "${f.oldQuote}"
Reasoning given: ${f.whyMissing}

Read the CURRENT full new page yourself and verify: is this information truly absent (not present anywhere, under any heading, in any form) from the new page? Default to real=false (not a genuine regression) if you're at all uncertain, if the fact is trivially inferable from the API signatures shown, or if it's a stylistic/structural difference rather than a factual omission.`,
      { phase: 'Verify', schema: VERDICT_SCHEMA, label: `verify:${f.module}` }
    ).then((v) => ({ ...f, verdict: v }))
  )
)

const confirmed = verified.filter(Boolean).filter((v) => v.verdict?.real)
log(`${confirmed.length}/${allFlags.length} confirmed as real regressions`)

return { flaggedCount: allFlags.length, confirmed }
```

## 7. Update — 2026-08-05, later same day: two root-cause fixes landed, re-verified against all 85

Picked up step 2 above. Diagnosing the 11 "Severe" items individually (fetching each module's real
published `.d.ts`) found they don't share one cause: **2 real, systemic `scripts/bare-refgen/`
bugs**, **~5 genuine upstream `.d.ts` gaps** (the type/member truly doesn't exist in what's
published — `RPCCommandRouter`, `import.meta`, TLS server methods, `isEnding`/`isFinishing`, same
class of issue as the already-known `bare-url#format` gap), and **2 modules (`bare-sdl`,
`bare-form-data`) that turned out to be hand-curated pages with no `api-model.json` behind them at
all** — not pipeline output, unrelated to `extract.ts`.

**Both fixable bugs are now fixed, on this branch, in two commits:**

- `5741e3b` — `fetch.ts` never installed a package's dependencies, only the one requested tarball.
  Since nearly every `bare-*` `.d.ts` imports types from sibling packages, those imports couldn't
  resolve — TypeScript degrades silently, so anything depending on that resolution (chiefly
  interface members inherited via `extends`) vanished with no error. Fixed by vendoring each
  package's `bare-*` dependency closure (recursively, deduped, `npm pack` only — no real install)
  into a shared run-scoped `node_modules`. `extract.ts`'s interface rendering also had to stop using
  raw `decl.getText()` (which never showed inherited members either way) in favor of
  `checker.getPropertiesOfType` — but still prints each member via its own declaration node, not
  `checker.typeToString`, so a cross-file member renders as `close: []`, never a resolved
  `import("/tmp/.../index").Type` path.
- Same commit — a top-level class/interface declared in a module's entry file but never exported
  (directly or via the `export =` namespace) was invisible even when clearly part of the public
  surface — e.g. bare-broadcast-channel's `connect(): Port<T>`, where `Port` has no export of its
  own. Added a reachability sweep in `extract.ts` promoting such symbols to top-level siblings, same
  as the existing namespace-export-table siblings.
- `59b249a` — regenerated every pipeline-eligible module page with both fixes applied (61 modules
  run; `bare-apk`/`bare-channel`/`bare-mime`/`bare-union-bundle` confirmed to ship no `.d.ts` at all
  currently, same situation as `bare-sdl`/`bare-form-data`, left untouched).

**Verified safe:** `bare-refs:changelog` across all 53 previously-tracked modules showed only
Added/Changed symbols, zero `⚠ removed`. `tsc --noEmit`, `check:bare-refs` (61/61),
`check:doctypes`, `check:internal-links`, `check:cross-links`, and `test:bare-refs` (7/7, incl. 2
new regression fixtures — `reachable.d.ts`, `events.d.ts`) all pass.

**Re-verified against the actual 85-item list** (background agent, module-by-module read of every
current page against every original finding): **4/85 fixed directly** — bare-broadcast-channel's
`Port`, bare-sidecar's `close`/`error` events, bare-subprocess's `constants` export/subpath,
bare-tcp's `family` connect option. That's the correct, expected number — these two bugs were never
going to fix the majority of the list, because **the majority of the 85 is a third, separate root
cause this pass didn't touch: `render.ts`'s `## See also` section only ever emits
`layout.seeAlso` (per-module, hand-curated) plus two generic catalog links — there is no
auto-generated "Builds on X, Y, Z" prose anywhere in the pipeline.** That's why "Related
modules"/"See also" loss reads as near-universal across the 85 regardless of which module: it's a
template gap, not a bug in any one module's extraction. (Worth noting: the dependency-vendoring fix
above now gives the pipeline exact, machine-readable knowledge of each module's `bare-*`
dependencies — `fetch.ts`'s `pkg.dependencies` — which is precisely the input a "Builds on …"
auto-generation feature would need. Not built here; flagged as the natural next lever.)

The other real gaps in the 85 that neither fix touches: the CLI-flags/worked-example sections
living outside README `## Usage` (bare-make, bare-pipe — the pipeline only ever pulls `## Usage`
verbatim, explicitly out of scope for this pass per an explicit scoping decision), and a handful of
narrower per-symbol gaps (`Condition.wait()`'s params, `Log` interface, TLS server methods) that
are either genuine upstream `.d.ts` gaps or extractor edge cases not covered by either bug fixed
here.

**Net effect beyond the 85-item list:** the two fixes changed 35 content pages total, not just the
