<Status level="stable" />

`Corestore` manages many related [Hypercores](/reference/building-blocks/hypercore) behind one storage root and one replication surface. It is the helper you usually share across [Hyperbee](/reference/building-blocks/hyperbee), [Hyperdrive](/reference/building-blocks/hyperdrive), and [Autobase](/reference/building-blocks/autobase) instances. For upstream source and changelog context, see the [Corestore repository](https://github.com/holepunchto/corestore).

## Install

```sh
npm i corestore
```

## Quickstart

```js
import Corestore from 'corestore'

const store = new Corestore('./app-storage')
await store.ready()

const messages = store.get({
  name: 'messages',
  valueEncoding: 'json'
})

await messages.ready()
await messages.append({ text: 'hello from corestore' })

console.log(await messages.get(0))

await store.close()
```

## API Reference

### Constructor and lifecycle

#### `const store = new Corestore(storage, options = {})`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L258)

Create a new Corestore instance.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `storage` | `string\|object` | — | can be either a `hypercore-storage` instance or a string. |
| `opts` | [`CorestoreOptions`](#corestoreoptions) | `{}` | Store options. |

| Option | Default | Description |
| --- | --- | --- |
| `primaryKey` | `null` | The primary key to use as the master key for key derivation. |
| `writable` | `true` |  |

#### `await store.ready()`

A promise that resolves once the storage seed is loaded and properties such as `store.primaryKey` are available.

#### `await store.close()`

Fully close this Corestore instance.

#### `await store.suspend()`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L426)

Suspend the underlying storage for the Corestore.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `options` | `object` | `{}` | Suspend options. |

- Returns: [`Promise<void>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) — Resolves once the storage is flushed and suspended.

```js
await store.suspend()
```

#### `await store.resume()`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L445)

Resume a suspended Corestore.

- Returns: [`Promise<void>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) — Resolves once the storage is resumed.

```js
await store.resume()
```

### Store properties

#### `store.storage`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L263)

The backing storage adapter used for aliases, seeds, and Hypercore data files.

- Returns: `object`

#### `store.primaryKey`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L279)

The 32-byte primary key used to deterministically derive writable named cores and namespaced key pairs.

- Returns: [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer)

#### `store.readOnly`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L276)

`true` when the store was opened without write access.

- Returns: `boolean`

#### `store.manifestVersion`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L282)

The Hypercore manifest version used when Corestore creates new writable cores.

- Returns: `number`

#### `store.active`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L285)

`true` when the store should automatically attach loaded cores to active replication streams.

- Returns: `boolean`

### Loading cores and scoping sessions

#### `const core = store.get(key | { name: 'a-name', ...hypercoreOpts})`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L716)

Loads a Hypercore, either by name (if the `name` option is provided), or from the provided key (if the first argument is a Buffer or String with hex/z32 key, or if the `key` options is set).

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `opts` | [`Buffer\|string\|object`](https://nodejs.org/api/buffer.html#class-buffer) | — | A key (Buffer/hex/z32 string), or an options object with `name`, `key`, or `discoveryKey` plus Hypercore options. |

- Returns: [`Hypercore`](/reference/building-blocks/hypercore) — A Hypercore session for the requested core.

```js
const core = store.get({ name: 'my-core' })
```

#### `const storeB = storeA.session()`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L457)

Create a new Corestore session. Closing a session will close all cores made from this session.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `opts` | `object` | — | Session options (forwarded to the new Corestore). |

- Returns: [`Corestore`](/reference/helpers/corestore) — A new Corestore session sharing the same storage.

```js
const session = store.session()
```

#### `const store = store.namespace(name)`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L480)

Create a new namespaced Corestore session. Namespacing is useful if you're going to be sharing a single Corestore instance between many applications or components, as it prevents name collisions.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | [`string\|Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | — | Namespace name; combined with the current namespace to derive a new one. |
| `opts` | `object` | — | Session options (forwarded to the new Corestore). |

- Returns: [`Corestore`](/reference/helpers/corestore) — A new namespaced Corestore session.

```js
const ns1 = store.namespace('a')
const ns2 = ns1.namespace('b')
const core1 = ns1.get({ name: 'main' }) // These will load different Hypercores
const core2 = ns2.get({ name: 'main' })
```

### Replication and discovery

#### `const stream = store.replicate(optsOrStream)`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L615)

Creates a replication stream that's capable of replicating all Hypercores that are managed by the Corestore, assuming the remote peer has the correct capabilities.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `isInitiator` | [`boolean\|Stream`](https://nodejs.org/api/stream.html) | — | `true`/`false` to initiate, or an existing stream/connection to replicate over. |
| `opts` | `object` | — | Replication options, forwarded to the protocol stream. |

- Returns: [`Stream`](https://nodejs.org/api/stream.html) — The replication stream.

```js
const swarm = new Hyperswarm()

// join the relevant topic
swarm.join(...)

// simply pass the connection stream to corestore
swarm.on('connection', (connection) => store.replicate(connection))
```

#### `store.findingPeers()`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L396)

A completion callback. Call it after the current peer-discovery pass finishes so pending update waits on loaded cores can unblock.

- Returns: `Function` — A `done` function to call once peer discovery has finished.

```js
const done = store.findingPeers()
swarm.flush().then(done, done)
```

#### `const stream = store.list(namespace)`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L495)

Creates a discovery key stream of all cores within a namespace or all cores in general if no namespace is provided.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `namespace` | [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | — | to scope to; omit to list all cores. |

- Returns: [`Readable`](https://nodejs.org/api/stream.html#class-streamreadable) — A stream of discovery keys.

```js
for await (const discoveryKey of store.list()) console.log(discoveryKey)
```

#### `store.getAuth(discoveryKey)`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L506)

The storage-layer auth metadata for that core, including manifest details when available.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `discoveryKey` | [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | — | Discovery key of the core to look up. |

- Returns: [`Promise<object\|null>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) — The auth record, or `null` if not stored.

```js
const auth = await store.getAuth(discoveryKey)
```

### Key derivation and maintenance

#### `const keypair = await store.createKeyPair(name, ns = this.ns)`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L782)

Generate a key pair seeded with the Corestore's primary key using a `name` and a `ns` aka namespace. `ns` defaults to the current namespace.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | `string` | — | to derive the key pair from. |
| `ns` | [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | `this.ns` |  |

- Returns: [`Promise<{publicKey: Buffer, secretKey: Buffer}>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) — The derived key pair.

```js
const keyPair = await store.createKeyPair('signer')
```

#### `store.audit(opts = {})`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L415)

An audit report describing the state of the backing store and any detected inconsistencies.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `opts` | `object` | `{}` | Audit options (e.g. `dryRun`). |

- Returns: `AsyncGenerator<object>` — Yields a result per core as it is audited.

```js
for await (const report of store.audit()) console.log(report)
```

#### `await store.staticify(core, opts)`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L663)

A reopened Hypercore whose manifest is converted into a static prologue-based manifest for the current data snapshot.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `core` | [`Hypercore`](/reference/building-blocks/hypercore) | — | The source core to snapshot. Must have data. |
| `opts` | `object` | — | Options forwarded to `store.get()` for the new |

- Returns: [`Promise<Hypercore>`](/reference/building-blocks/hypercore) — The new static Hypercore.

```js
const staticCore = await store.staticify(core)
```

### Watchers

#### `store.watch((core) => {})`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L315)

Register a callback called when new Hypercores are opened. `core` is the internal core for the opened Hypercore. It can be used to create weak references to a Hypercore like so:

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `fn` | `Function` | `> {}` | Callback invoked with the internal `core` each time a Hypercore is opened. |

- Returns: `void`

```js
store.watch(function (core) {
  const weakCore = new Hypercore({ core, weak: true })
})
```

#### `store.unwatch(callback)`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L332)

Unregister a callback used with `store.watch(callback)` so it no longer fires.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `fn` | `Function` | — | The callback previously passed to `store.watch()`. |

- Returns: `void`

```js
store.unwatch(onCore)
```

### Group notifications (experimental)

#### `const handle = store.notifyGroup(topic)`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L360)

Get a `handle` for updates from all `hypercore`s with the group `topic` set.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `topic` | [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | — | The 32-byte group topic to watch. |

- Returns: [`GroupNotifyHandle`](/reference/helpers/corestore) — A handle that emits `update` when a core in the group changes.

```js
const handle = store.notifyGroup(topic)
handle.on('update', () => console.log('group changed'))
```

<Callout type="warn">
Group notifications are experimental. The API is subject to change and may break in any release.
</Callout>

#### `const stream = handle.update(opts = {})`

Gets updates for the `topic` the handle is for.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `opts` | — | `{}` | includes |

| Option | Default | Description |
| --- | --- | --- |
| `since` | `0` | What timestamp to start returning updates from. Default `0` returns all updates |
| `reverse` | `true` | Flag to return updates in reverse order. Defaults to `true` so latest returned first |

```js
for await (const key of handle.updates()) {
  // ...
}
```

#### `handle.destroy()`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/lib/notify.js#L24)

Destroys and unregisters the `handle` from its `store`.

#### `handle.on('update', callback)`

Calls the callback whenever a core with the `topic` for the `handle` updates.

#### `store.on('group-active', (topic) => {})`

[API definition on GitHub](https://github.com/holepunchto/corestore/blob/v7.10.1/index.js#L344)

The `group-active` event emits whenever an opened Hypercore in the store updates. The `topic` is the group topic the core belongs to.

## Types

### CorestoreOptions

Options for the \{@link Corestore\} constructor. Any other options are forwarded
to the underlying `hypercore-storage` instance.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `primaryKey` | [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | — | The 32-byte master key from which all writable named cores are derived. Generated and persisted automatically when omitted. |
| `writable` | `boolean` | `true` | Set to `false` to open the store read-only; loaded cores default to read-only too. |
| `readOnly` | `boolean` | `false` | Open the backing storage in read-only mode. |
| `active` | `boolean` | `true` | Whether loaded cores are automatically attached to active replication streams. |
| `unsafe` | `boolean` | `false` | Acknowledge that passing `primaryKey` directly is unsafe; required when `primaryKey` is set on a root store. |
