[`bare-wasi`](https://github.com/holepunchto/bare-wasi) — Capability based WASI for JavaScript.

```sh
npm i bare-wasi
```

## Usage

```js
const wasm = require('bare-wasm')
const WASI = require('bare-wasi')
const { MemoryDirectory } = require('bare-wasi/memory')

const wasi = new WASI({
  version: 'preview1',
  args: ['program'],
  preopens: {
    '/data': new MemoryDirectory({ 'hello.txt': 'Hello from JavaScript' })
  },
  stdout: (data) => console.log(data.toString())
})

const module = new wasm.Module(bytes)
const instance = new wasm.Instance(module, wasi.getImportObject())

const exitCode = wasi.start(instance)
```

The `version` option is required and must be `'preview1'` so that options are always read for the version of WASI they were written for.

## API

### WASI

#### `new WASI(opts: WASIOptions)`

Create a WASI implementation for a single instance.

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `opts` | [`WASIOptions`](#wasioptions) | — | The capabilities of the instance. `version` is required and must be `'preview1'`. `args` defaults to `[]`, `env` to `{}`, and `preopens` to `{}`. `stdin`, `stdout`, and `stderr` default to `null`, and then don't exist. `clock` defaults to the host clocks, and `null` denies them. `random` defaults to `null`, which denies randomness. `returnOnExit` defaults to `true`; with `false`, `start()` exits the process with the guest's exit code. |

#### `getImportObject(): { wasi_snapshot_preview1: Record<string, (...args: any[]) => number> }`

Get an import object to pass when instantiating a WebAssembly module.

#### `initialize(instance: WASIInstance): void`

Initialize a reactor instance by calling its `_initialize()` export, if it
has one. The instance must export its `memory` and must not export
`_start()`, and an implementation may only be used with a single instance.

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `instance` | [`WASIInstance`](#wasiinstance) | — | The instance to initialize. |

#### `start(instance: WASIInstance): number | undefined`

Run the `_start()` export of a command instance. The instance must export
its `memory` and must not export `_initialize()`, and an implementation
may only be used with a single instance.

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `instance` | [`WASIInstance`](#wasiinstance) | — | The instance to run. |

**Returns** `number` | `undefined` — The exit code of the program, if `returnOnExit` is `true`. The
process is exited with it otherwise.

#### `WASINode`

```ts
interface WASINode {
```


#### `WASIDirectory`

```ts

  readonly type: 'directory'
  lookup(name: string): WASINode | null
  entries(): Iterable<[name: string, node: WASINode]>
  create(name: string, type: 'file' | 'directory'): WASIFile | WASIDirectory
```

## `bare-wasi/host`

### HostDirectory

#### `new HostDirectory(directory: DirectorySync)`

A host directory backed by a `bare-directory` capability. The guest reaches only what the capability reaches, with its rights, and `bare-wasi` resolves symbolic links within the preopen. On Windows, link targets use `/` as the separator, and drive letter, UNC, and device paths are absolute. Files are opened when looked up, with the most access the rights and the file allow, so an open file stays the same file if it is renamed. Creating symbolic and hard links isn't supported.

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `directory` | `DirectorySync` | — | The `bare-directory` capability to expose to the guest. |

#### `create: WASIDirectory['create']`

Implements [`WASIDirectory.create()`](#wasidirectory).

#### `entries: WASIDirectory['entries']`

Implements [`WASIDirectory.entries()`](#wasidirectory).

#### `lookup: WASIDirectory['lookup']`

Implements [`WASIDirectory.lookup()`](#wasidirectory).

#### `rename: WASIDirectory['rename']`

Implements [`WASIDirectory.rename()`](#wasidirectory). Renaming into a directory of another backend fails with `EXDEV`. The capability needs `rename` on both directories and `remove` on the target, even when no entry is replaced.

#### `rmdir: WASIDirectory['rmdir']`

Implements [`WASIDirectory.rmdir()`](#wasidirectory).

#### `setTimes: NonNullable<WASIDirectory['setTimes']>`

Implements [`WASINode.setTimes()`](#wasinode).

#### `host.HostDirectory.size: number`

The number of entries of the directory.

#### `stat: WASIDirectory['stat']`

Implements [`WASINode.stat()`](#wasinode).

#### `host.HostDirectory.type: 'directory'`

The type of the node, which is always `'directory'`.

#### `unlink: WASIDirectory['unlink']`

Implements [`WASIDirectory.unlink()`](#wasidirectory).

## WebAssembly addons

From Bare 1.36.0, the module system loads an addon compiled to WebAssembly through [`bare-wasm-abi`](/bare/reference/bare/modules/bare-wasm-abi), which creates one `WASI` instance per addon. The options for it come from a WASI provider: a module that exports a function, which is called with the `URL` of each WebAssembly addon and returns the options described by [`WASIOptions`](#wasioptions). An importer names the provider with the `wasi` import attribute. See [`bare-module`](/bare/reference/bare/modules/bare-module#webassembly-addons).

```js
const { DirectorySync } = require('bare-directory')
const { HostDirectory } = require('bare-wasi/host')
const crypto = require('bare-crypto')

module.exports = (url) => ({
  version: 'preview1',
  preopens: {
    '/': new HostDirectory(DirectorySync.open(__dirname + '/data'))
  },
  random: (buffer) => crypto.randomFillSync(buffer)
})
```

An addon with no provider gets the options `{ version: 'preview1' }`, which grant nothing except clocks. Bare has no `crypto` global, so take random bytes from [`bare-crypto`](/bare/reference/bare/modules/bare-crypto) when an addon needs them. An addon written in Rust can need them: the `bare-svg` README says its WebAssembly build needs `random` because the Rust standard library seeds its hash maps with it.

## Compared with Node.js

The class has the shape of `WASI` in the Node.js [`wasi`](https://nodejs.org/api/wasi.html) module: `new WASI(options)` with a required `version`, `getImportObject()`, `start()`, `initialize()`, and `wasiImport`. The options differ in what they hand to the guest:

| Option | `bare-wasi` | Node.js `wasi` |
| --- | --- | --- |
| `preopens` | Map guest paths to directory backends, such as `MemoryDirectory` or `HostDirectory`. | Map guest paths to host paths. |
| `stdin`, `stdout`, `stderr` | Contents, functions, streams, or files. Absent unless given. | File descriptors, `0`, `1`, and `2` by default. |
| `random` | Denied unless a function is given. | Always available. |
| `clock` | Host clocks, or `null` to deny them. | Always available. |

Node.js documents that its `wasi` module does not provide the comprehensive file system security properties of some WASI runtimes. `bare-wasi` resolves every path itself, one name at a time, and a `HostDirectory` is also confined by the kernel.

## Capabilities

Every resource a guest can reach is passed in by the embedder:

- **Streams.** Standard input, output, and error exist only if `stdin`, `stdout`, and `stderr` are given.
- **Directories.** A guest can only reach the directories given as `preopens`, and paths are resolved by `bare-wasi` itself, one name at a time. Absolute paths, symbolic links that point outside of a directory, and `..` beyond where a lookup started all fail with `ENOTCAPABLE`.
- **Clocks.** Clocks are available by default, as they are to any JavaScript, and can be denied with `clock: null`.
- **Randomness.** `random_get` fails with `ENOTCAPABLE` unless a `random` function is given.

Beyond these, a guest only sees the arguments and environment variables it is given. There are no sockets.

## Conformance

`bare-wasi` passes the WASI preview 1 tests of the [WASI test suite](https://github.com/WebAssembly/wasi-testsuite), which are fetched at a pinned commit and run as part of `npm test`. Tests that are known to fail are listed with the reason in [`test/suite.json`](https://github.com/holepunchto/bare-wasi/blob/main/test/suite.json), and a listed test that starts passing fails the run.

## Backends

Preopens are backed by objects implementing a small, synchronous interface. Directories are only ever asked about a single name, never a path, which keeps the resolution of paths, and so the enforcement of capabilities, in one place. Failures are reported by throwing errors with a POSIX `code`, such as `'ENOENT'`. See [`WASIDirectory`](#wasidirectory), [`WASIFile`](#wasifile), and [`WASISymlink`](#wasisymlink) for the interface.

### In memory

```js
const { MemoryDirectory, MemoryFile, MemorySymlink } = require('bare-wasi/memory')

const directory = new MemoryDirectory({
  'file.txt': 'contents',
  nested: { 'data.bin': new Uint8Array([1, 2, 3]) }
})
```

### Host

Directories of the host filesystem are backed by [`bare-directory`](/bare/reference/bare/modules/bare-directory) capabilities. They confine every operation to the directory in the kernel as well, and limit it to the rights the capability has.

```js
const { DirectorySync } = require('bare-directory')
const { HostDirectory } = require('bare-wasi/host')

const directory = new HostDirectory(
  DirectorySync.open('/srv/data', { rights: ['list', 'lookup', 'read'] })
)
```
