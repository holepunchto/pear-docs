[`bare-bluetooth-android`](https://github.com/holepunchto/bare-bluetooth-android) — Android Bluetooth bindings for Bare. It is a native addon.

```sh
npm i bare-bluetooth-android
```

## Usage

```js
const { Central } = require('bare-bluetooth-android')

const central = new Central()

central.on('stateChange', (state) => {
  if (state === 'on') {
    central.startScan(['180D']) // Heart Rate service UUID
  }
})

central.on('discover', (peripheral) => {
  console.log('Found:', peripheral.name, peripheral.id)
  central.stopScan()
  central.connect(peripheral)
})

central.on('connect', (peripheral) => {
  peripheral.discoverServices()

  peripheral.on('servicesDiscover', (services) => {
    // Discover characteristics for each service
  })
})
```

### Server

#### `new Server()`

Create a new BLE peripheral server. Call `open()` once `state` is `'on'` before using it.

**Parameters**

Destroy the server, stopping advertising and unpublishing all L2CAP channels.

## Events

Each class is an `EventEmitter`. These are the events each one emits and the arguments they carry. Failures arrive as `'error'` events; see [Errors](#errors) for the other ways a call can fail.

### `Central` events

| Event | Arguments | Description |
| --- | --- | --- |
| `'stateChange'` | `state: BluetoothState` | The adapter state changed. |
| `'discover'` | `peripheral: Peripheral` | A peripheral was found while scanning. Repeated advertisements from the same device reuse the same `Peripheral`. |
| `'connect'` | `peripheral: Peripheral` | A connection was established. |
| `'disconnect'` | `peripheral: Peripheral \| null` | A peripheral disconnected, or `null` if it was not tracked as connected. If the disconnect carried an error, `'error'` is emitted with code `DISCONNECT` instead. |
| `'error'` | `error: BluetoothError` | An operation failed: `SCAN_FAILED`, `CONNECTION_FAILED` or `DISCONNECT`. The last two carry the device address as `error.id`. |

### `Peripheral` events

| Event | Arguments | Description |
| --- | --- | --- |
| `'servicesDiscover'` | `services: Service[]` | Result of `discoverServices()`. |
| `'characteristicsDiscover'` | `service: Service \| null, characteristics: Characteristic[]` | Result of `discoverCharacteristics()`. |
| `'read'` | `characteristic: Characteristic, data: Uint8Array` | A read completed. |
| `'write'` | `characteristic: Characteristic` | A write completed. |
| `'notify'` | `characteristic: Characteristic, data: Uint8Array` | A subscribed characteristic changed value. |
| `'notifyState'` | `characteristic: Characteristic, isNotifying: boolean` | Notifications were turned on or off for the characteristic. |
| `'channelOpen'` | `channel: L2CAPChannel` | An L2CAP channel opened (result of `openL2CAPChannel()`). |
| `'mtuChanged'` | `mtu: number` | The MTU changed (result of `requestMtu()`). |
| `'disconnect'` | none | The peripheral disconnected without error. |
| `'error'` | `error: BluetoothError` | An operation failed, for example `READ_FAILED`, `CHANNEL_FAILED` or `MTU_CHANGE_FAILED`. |

The type declarations allow `null` for the characteristic of `'read'`, `'write'`, `'notify'` and `'notifyState'`, but the module drops those events for a characteristic the peripheral has not discovered rather than emitting `null`.

### `Server` events

| Event | Arguments | Description |
| --- | --- | --- |
| `'stateChange'` | `state: BluetoothState` | The adapter state changed. Call `open()` again after every transition back to `'on'`. |
| `'serviceAdd'` | `uuid: string` | A service was registered with the GATT server (result of `addService()`). |
| `'channelPublish'` | `psm: number` | An L2CAP channel was published, with its assigned PSM. |
| `'channelOpen'` | `channel: L2CAPChannel` | A remote device opened a published L2CAP channel. |
| `'readRequest'` | `request: ReadRequest` | A client asked to read a characteristic. Every read reaches this event; answer it with `respondToRequest()`. |
| `'writeRequest'` | `requests: WriteRequest[]` | A client wrote to a characteristic. If `responseNeeded` is set, answer with `respondToRequest()`. |
| `'subscribe'` | `deviceAddress: string, characteristicUuid: string` | A connected device subscribed to notifications for a characteristic. |
| `'unsubscribe'` | `deviceAddress: string, characteristicUuid: string` | A connected device unsubscribed from notifications for a characteristic. |
| `'connecting'`, `'connected'`, `'disconnecting'`, `'disconnected'` | `deviceAddress: string` | The connection state of a remote device changed. |
| `'notifySent'` | `deviceAddress: string, status: number` | A notification was sent to a device, with the platform status code. |
| `'error'` | `error: BluetoothError` | An operation failed: `SERVICE_ADD_FAILED`, `ADVERTISE_FAILED`, `CHANNEL_PUBLISH_FAILED` or `CHANNEL_FAILED`. |

## Errors

Failures arrive three ways:

- **Thrown** - the Android call itself failed. The message carries the Java exception, for example `java.lang.IllegalStateException: BT Adapter is not turned ON`. Wrap the call in `try`/`catch`.
- **Emitted** - the call went through and the operation failed later. The `error` event carries a `BluetoothError` with a `code` such as `SCAN_FAILED` or `CONNECTION_FAILED`.
- **Streamed** - an `L2CAPChannel` is a `Duplex`, so a failed write does not throw from the write itself. It destroys the stream with the Java exception, for example `java.io.IOException: Broken pipe` once the peer is gone. Listen for `error` on the channel; an unhandled one still throws.
