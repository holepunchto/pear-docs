[`bare-logger`](https://github.com/holepunchto/bare-logger) — Low-level logger for Bare. It is a native addon.

```sh
npm i bare-logger
```

## Usage

```js
const Log = require('bare-logger')

const log = new Log()

log.info('Hello %s', 'world!')
```

## API

### Log

#### `new Log(options?: LogOptions)`

Create a logger. `debug()` and `info()` write to standard output, and `warn()`, `error()`, and `fatal()` to standard error, one line per call. `colors` defaults to whether both standard output and standard error are TTYs. Fixed in v2.0.5: if something in the process had made standard output or standard error non-blocking, as libuv does when it opens a stream on one, lines written while the pipe was full went missing or were cut short.

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `options?` | [`LogOptions`](#logoptions) | — | Logger options; `colors` forces ANSI color styling on or off, defaulting to whether both standard output and standard error are TTYs. |

#### `Log.clear(): void`

Clears the log output. A no-op on the base `Log`.

#### `Log.colors: boolean`

Whether this logger applies ANSI color styling to formatted output. Read-only.

#### `Log.debug(...data: unknown[]): void`

Logs `data` at debug level.

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `data` | `unknown[]` | — | Values to format and log; the first may be a `printf`-style format string (for example `%s`, `%d`, `%o`) with the remaining values as substitutions. |

#### `Log.error(...data: unknown[]): void`

Logs `data` at error level.

**Parameters**

#### `Log.fatal(...data: unknown[]): void`

#### `LogOptions`

```ts

```

## Threat model

`bare-logger` is one of the addons Bare compiles into its binary, so every Bare process has it, sealed or not, and it inherits [Bare's threat model](https://github.com/holepunchto/bare/blob/main/docs/threat-model.md). The module's own [threat model](https://github.com/holepunchto/bare-logger/blob/main/docs/threat-model.md), added in v2.0.5, says where it sits in that one. It writes to the standard output and standard error the process was given, which is how `console` writes in a default build, and opens nothing else. Whatever sealed code logs goes wherever those two go, so treat them as a way out of the process: sealed code can put any bytes into a file, pipe, or device log at the far end, and escape sequences into a terminal. That sealed code can write to them is not a bug. A memory bug in the C that formats strings and converts them to UTF-8, or any way to reach another file descriptor, is.

## Multiple loggers

`CompositeLog` can be used to output to multiple loggers. Such as console and file loggers.

```js
const { Log, CompositeLog } = require('bare-logger')

const log1 = new Log()
const log2 = new Log()
const log = new CompositeLog([log1, log2])

log.info('Hello %s', 'world!')
```
