[`bare-stow`](https://github.com/holepunchto/bare-stow) — Module bundling and harness generation for Bare.

```sh
npm i bare-stow
```

## Usage

The entry module exports a `start()` function that receives the IPC stream and an optional `ready` callback. It may return a function to run before the bundle exits:

```js
module.exports = async function start(ipc, ready) {
  ipc.on('data', (data) => {
    // Handle messages from the host.
  })

  // Signal readiness early. Otherwise, it's signaled when `start()` resolves.
  ready()

  return async function stop() {
    // Clean up before the bundle exits.
  }
}
```

If a `server` is requested, `start()` instead receives `{ rpc, ipc }`, with `rpc` bound to the IPC stream. Its handlers are registered in `start()`, before the bundle signals ready:

```js
module.exports = function start({ rpc }) {
  rpc.respond(1, (req, data) => data)
}
```

Stow it for a target:

```js
const stow = require('bare-stow')

const entry = 'file:///app/core.js'
const out = 'file:///app/core-harness/'

for await (const artifact of stow(entry, 'bare-sidecar', out)) {
  console.log(artifact.url.href)
}
```

Or from the command line:

```console
$ bare-stow pack --target bare-sidecar --out ./core-harness ./core.js
```

This writes a package to `out` with the harness, the bundle, and a manifest declaring the dependencies of the harness. `stow()` yields each file once written, and the bundle along with its `base`, the directory that its modules are named relative to. It's the `base` option if given, and otherwise the closest directory containing every module. Add the package as a dependency of the host and boot the bundle with `start()`, which resolves once the bundle is ready:

```js
import * as harness from 'core-harness'

const { ipc } = await harness.start()

ipc.write(Buffer.from('hello from the host'))

// Request a graceful shutdown, which resolves with the exit code.
const code = await ipc.terminate()
```

The bundle imports `bare-stow-runtime`, and the RPC library if a `server` is requested, so the package containing the entry must depend on them. For `bare-rpc`, that is `bare-rpc` and `bare-abort-controller`, which gives handlers the `signal` that aborts when the peer cancels a request.

`start()` accepts `timeout`, how long to wait in milliseconds for the bundle to signal ready, and `grace`, how long a terminating bundle gets to run `stop()` and exit before it's killed. `timeout` defaults to waiting indefinitely and `grace` to 5 seconds. On Windows, a sidecar is killed along with its host, so `stop()` only runs when the host terminates it.

For `bare-sidecar` and `bare-worker`, the harness also exports `connect()`, which takes a sidecar or worker that the host started itself, such as one running a development entry with arguments, and resolves like `start()`. It accepts the same options, except those of the sidecar or worker. As the entry doesn't go through `stow()`, it attaches to the IPC itself, as described in [https://github.com/holepunchto/bare-stow-runtime](https://github.com/holepunchto/bare-stow-runtime):

```js
const runtime = require('bare-stow-runtime/process')

const ipc = runtime.attach(Bare.IPC)

ipc.run(() => import('./core.js'), ipc)
```

```js
const sidecar = new Sidecar('./dev.js', ['--verbose'], { stdio: 'inherit' })

const { ipc } = await harness.connect(sidecar)
```

`stow()` and `link()` read the module graph from disk by default. To read it from elsewhere, such as modules that aren't written to disk, pass `readModule`, `listPrefix`, and `resolveModule`. Generated files are still written to disk. A `readModule` that changes the type of a module also passes `aliases`, as for [https://github.com/holepunchto/bare-pack](https://github.com/holepunchto/bare-pack), such as `{ '.mjs': '.js' }` to have ES modules converted to CommonJS loaded as such. They're merged over the aliases that `bare-stow` uses for TypeScript.

## API

### Functions

#### `stow`

```ts
stow(entry: URL | string, target: Target | TargetName, out: URL | string, opts?: StowOptions): AsyncGenerator<StowArtifact>
```

Bundle the module graph rooted at `entry` for `target`, writing a harness package plus bundle to `out`.

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `entry` | `URL` \| `string` | — | The entry module to bundle, as a `file:` URL or path string. |
| `target` | [`Target`](#target) \| `TargetName` | — | The bundling target: a `Target` object, or a target name resolved to one (the built-in `bare-kit`, `bare-sidecar`, and `bare-worker`, or a `bare-stow-target-<name>` package). |
| `out` | `URL` \| `string` | — | The directory to write the harness package to, as a `file:` URL or path string. |
| `opts?` | [`StowOptions`](#stowoptions) | — | Options; see [`StowOptions`](#stowoptions). |

**Returns** `AsyncGenerator<StowArtifact>` — An async generator that yields each written artifact's `url` as it is produced: any addons linked into the package, the harness and its type declaration, the RPC client and its type declaration, the package manifest, the bundle along with its `base`, and then any assets of a linked bundle, any offloaded addon or asset files, and the listing of those files.

**Throws**

- The `target` argument is missing.
- The `out` argument is missing.
- A language option is unknown or invalid, or `out` is not valid as a package.
- The target or an RPC library does not support the language.
- A host in `opts.hosts` is not supported by the resolved target in the language.

#### `stow.link`

```ts
stow.link(entries: URL | string | (URL | string)[], target: Target | TargetName, out: URL | string, opts?: LinkOptions): AsyncGenerator<StowArtifact>
```

Link the addons and assets of the graphs rooted at `entries` into a package at `out`, once for an application. The language lays out the package and the target adds what loads the addons. The module exported it before v0.3.3, but only v0.3.3 and later declare its types.

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `entries` | `URL \| string \| (URL \| string)[]` | — | The entry modules of the graphs, as `file:` URLs or path strings. |
| `target` | [`Target`](#target) \| `TargetName` | — | The target the graphs are stowed for, or its name. |
| `out` | `URL` \| `string` | — | The directory to write the package to, as a `file:` URL or path string. |
| `opts?` | [`LinkOptions`](#linkoptions) | — | Options; see [`LinkOptions`](#linkoptions). |

**Returns** `AsyncGenerator<StowArtifact>` — An async generator that yields the `url` of each linked addon and asset, and then of the module and manifest of the package.

**Throws**

- `entries` is empty, or the `target` or `out` argument is missing.
- The target does not link addons, or does not support linking for the language.
- The language does not support linked addons or assets.
- Two different assets would link to the same path.

## Targets

- `bare-sidecar` runs the bundle in a separate process using [https://github.com/holepunchto/bare-sidecar](https://github.com/holepunchto/bare-sidecar), with the `javascript`, `python`, and `swift` languages on desktop. In JavaScript and Python, `start()` also accepts the options of `bare-sidecar`.
- `bare-worker` runs the bundle in a thread of a Bare host using [https://github.com/holepunchto/bare-worker](https://github.com/holepunchto/bare-worker), with the `javascript` language.
- `bare-kit` runs the bundle in a worklet using [https://github.com/holepunchto/bare-kit](https://github.com/holepunchto/bare-kit), with the `swift` language on macOS and iOS and the `kotlin` language on Android and the JVM. `start()` also accepts the options of the worklet and returns it alongside `ipc`, and on Android takes the `Context` first. In Kotlin, the worklet is closed once it exits, so it needs no closing of its own, and in Swift it's released with its last reference. Native addons are linked with [https://github.com/holepunchto/bare-link](https://github.com/holepunchto/bare-link) and declared in the manifest, and assets are written next to the bundle. With the target option `linking` set to `'app'`, both are left to `link()` instead. On the JVM, addons and assets are written next to the bundle as files, which `start()` extracts along with the bundle to a temporary directory, so `linking` must be `'package'`.

## Linking

A target may leave addons and assets to the application, so that bundles sharing them don't each bring a copy. For `bare-kit`, stow each bundle with the target option `linking` set to `'app'`:

```console
$ bare-stow pack --target bare-kit --target-option linking=app --language swift --out ./ios/Core ./core.js
```

`link()` then links the addons and assets of all bundles once, into a package the application depends on:

```js
const entries = [new URL('file:///app/core.js'), new URL('file:///app/push.js')]
const out = new URL('file:///app/ios/BareKitAddons/')

for await (const artifact of stow.link(entries, 'bare-kit', out, { language: 'swift' })) {
  console.log(artifact.url.href)
}
```

The language lays out the package and the target adds what loads the addons. For `bare-kit`, that's `bare-kit-swift` or `bare-kit-kotlin`. The assets go in a folder named by `stow.resources`, listed in a file of the same name with the `.assets` extension, which a Swift application copies into its bundle. `link()` takes the same options as `stow()`, except `client` and `base`.

## Languages

The harness is generated in one of these languages, selected with `language` and configured with `languageOptions`:

- `javascript` writes an npm package. The `module` option is either `'esm'`, the default, or `'cjs'`.
- `kotlin` writes a Gradle module. The `package` option names the package of the generated code and is required. The `platform` option is either `'android'`, the default, for an Android library module, or `'jvm'` for a Kotlin/JVM library module on Linux, macOS, and Windows. The dependencies are published to JitPack ([https://jitpack.io](https://jitpack.io)), so add it to the repositories of the application.
- `python` writes a Python package.
- `swift` writes a Swift package.

For example, with an RPC client and server:

```console
$ bare-stow pack --target bare-sidecar --language python --client bare-rpc --server bare-rpc --out ./my-core ./core.js
```

```python
import asyncio

import my_core

async def main():
    ipc, rpc = await my_core.start(
        handlers=lambda router: router.on_request(2, lambda req: b"hello")
    )

    await rpc.request(1, b"ping")
    await ipc.terminate()

asyncio.run(main())
```

With an RPC client, `start()` takes the handlers for the requests and events of the bundle, so that they are registered before the bundle can send any.

Changed in v0.3.6: the generated code depends on the releases of `bare-rpc` that support cancellation: `bare-rpc` 2.x and `bare-abort-controller` in the bundle, and `bare-rpc-swift` 3.x, `bare-rpc-kotlin` 0.6.x, or `bare-rpc` 0.3.x for Python in the harness. See [Changes in v2.0.0](/bare/reference/bare/modules/bare-rpc#changes-in-v200) on the `bare-rpc` page.

## Protocol

The harness and the bundle multiplex a control channel and the user data over a single duplex stream. The `ipc` returned from `start()` is a duplex stream of the user data, so RPC libraries such as `bare-rpc` bind to it like any other stream. Embedders bringing their own transport can use the protocol directly:

- [https://github.com/holepunchto/bare-stow-protocol](https://github.com/holepunchto/bare-stow-protocol) implements the framing.
- [https://github.com/holepunchto/bare-stow-host](https://github.com/holepunchto/bare-stow-host) implements the host side and documents `ipc`, with [https://github.com/holepunchto/bare-stow-host-kotlin](https://github.com/holepunchto/bare-stow-host-kotlin), [https://github.com/holepunchto/bare-stow-host-python](https://github.com/holepunchto/bare-stow-host-python), and [https://github.com/holepunchto/bare-stow-host-swift](https://github.com/holepunchto/bare-stow-host-swift) for the other languages.
- [https://github.com/holepunchto/bare-stow-runtime](https://github.com/holepunchto/bare-stow-runtime) implements the bundle side.

## Providers

Languages, targets, and RPC libraries are providers that may live outside `bare-stow`. `stow()` and `link()` accept a provider object in place of a name, and names other than the built-in ones are resolved through `resolveLanguage`, `resolveTarget`, and `resolveRPC`. For example, [https://github.com/holepunchto/bare-stow-target-react-native](https://github.com/holepunchto/bare-stow-target-react-native) is a target for React Native. Targets and RPC libraries generate code for each language they list under `languages`, and providers without an entry for the language of the harness are rejected. Targets may also take options, given as `targetOptions`. The server side of an RPC library is always generated as JavaScript, as the bundle runs in Bare. See `index.d.ts` for the interfaces.

## CLI

#### `bare-stow pack [flags] <entry>`

Stow the module graph rooted at `<entry>` into the directory given by `--out`.

```console
--target <name>
--target-option <key=value>
--language <name>
--language-option <key=value>
--client <name>
--server <name>
--base <path>
--out|-o <path>
--builtins <path>
--imports <path>
--defer <specifier>
--host <name>
--help|-h
```

#### `bare-stow link [flags] <entry...>`

Link the addons and assets of the module graphs rooted at each `<entry>` into the package given by `--out`.

```console
--target <name>
--target-option <key=value>
--language <name>
--language-option <key=value>
--server <name>
--out|-o <path>
--builtins <path>
--imports <path>
--defer <specifier>
--host <name>
--help|-h
```

`--target`, `--language`, `--client`, and `--server` take a built-in name, the name of a `bare-stow-target-<name>`, `bare-stow-language-<name>`, or `bare-stow-rpc-<name>` package, or a module specifier, resolved from the working directory. `--target-option`, `--language-option`, `--defer`, and `--host` may be passed multiple times. `--host` must name hosts the target supports, and defaults to all of them.

`--builtins` and `--imports` are paths to JavaScript or JSON files exporting a list of builtin modules and a map of import overrides, which are forwarded to `bare-pack`.
