# Pear CLI

The `pear` command line tool builds, stages, and manages peer-to-peer
desktop and terminal apps. This covers **Pear v3**; `pear run` and
`pear release` were both removed in v3 and have no drop-in replacement
command — see below.

Key concepts:
- `pear touch` — mint a `pear://<key>` link. Needed before `pear stage` or `pear build` can write anywhere.
- `pear build` — assemble a multi-architecture deployment directory from per-OS Electron makes. From 3.6.0 it prints the app, version, and target, then one `+ <file> (origin: <source>)` line per artifact and `Build complete!`; before that it printed nothing on success. With `--json` it emits `building` (`name`, `version`, `target`), one `executable` (`file`, `origin`) per artifact, and `final`. An `executable` event has no architecture field: read the `by-arch/<arch>` segment of `file`.
- `pear make [entry]` — from 3.7.0, build a standalone executable of a Pear CLI app by running the `pear-make` CLI (`--host`, `--path`, `--name`, `--version|-v`, `--json`). `entry` defaults to the `bin` path in `package.json`. When `pear-make` is not on the `PATH`, the first run installs it after you type `INSTALL`. When stdin is not a terminal, or with `--json`, a missing `pear-make` fails with `ERR_NOT_FOUND` unless you pass `--install`, which does not reinstall over an existing copy. `--no-install` skips the check.
- `pear stage <link> [dir]` — sync local changes to the link's hypercore (a preview/staging sync, not a production release).
- `pear provision` + `pear multisig` — the v3 production release path: provision block-syncs a staged build to a pre-production target, multisig cosigns it onto the production link with a quorum of keys. This replaced the old single-key `pear release` command.
- `pear seed <link>` — seed a link so peers can fetch it. From 3.6.0 the `App:` name and version follow the drive as it updates, so a long-running seeder needs no restart across a release. It also reports its uptime: an `Uptime:` row in the live view, a `, uptime <time>` suffix on the `--no-tty` network line, and `uptime` (milliseconds) in the `--json` `stats` object. From 3.7.0 the network line shows `joining`, `unstable`, or `unreachable` in place of the peer and transfer counts when the DHT is not healthy, and `--json` `stats` gains `dht` (`bootstrapped`, `degraded`, `online`). From 3.7.0 it also exits with code 1 when the sidecar connection closes, printing `x-x sidecar lost` (live view) or `x-x sidecar disconnected` (`--no-tty`), or an `error` object with `code: ERR_CONNECTION` (`--json`), so a supervisor such as systemd or launchd can restart it. On 3.6.0 and earlier it kept running with the last stats frozen. The `Seeding:` row shows `pear://<key>`, without a verlink's version or any quotes, from 3.7.0.
- `pear install pear://<key>` — install a built app from the swarm. From 3.6.0 it exits with code 1 when the install fails.
- `pear info` / `pear dump` / `pear changelog` / `pear cores` — read-only inspection, no writes. From 3.6.0 `pear info` reports `writable`: whether this machine holds the key pair for the link, so it can stage to it. It applies to stage and provision links, not a multisig production link, and it does not prove a stage will succeed. A link with nothing on this machine yet reports `empty` instead of an `info` object. From 3.7.0 the human-readable output is a list of labeled rows (`Info:`, `Verlink:`, `App:`, `Writable:`, `Targets:`, `Drive Key:`, `Blobs Key:`, ...) instead of the `keys` and `info` tables, and `Targets:` lists each `by-arch/<platform>-<arch>` folder in the drive with its size, so the platforms a release carries can be read from the link without downloading the files' contents. The multisig section prints `Multisig Quorum:` and `Public Signing Keys:` instead of a `multisig` table. `--json` `info` gains `targets` (`[{ platform, size }]`) and `blobs.key`, and `retrieving` reports `link` (a `pear://` link) instead of `z32`. Select the `info` line to read it: `pear info --json <link> | jq -r 'select(.tag == "info") | .data.targets[].platform'`.
- `pear blind-peer start|request`, `pear blind-relay start`, and the global `--relay <key>` flag — run a blind peer or relay, or route connections through one.
- `pear identity seed|blind-relay|blind-peer|blind-peer-client` — print one of this machine's network keys, for another machine to pass to `pear seed --until-sync`, `--relay`, `pear seed --blind-peer`, or `pear blind-peer start --trusted-peer`. Replaced `pear blind-peer identity` in 3.5.0.
- Link arguments may be wrapped in one matching pair of single or double quotes from 3.6.0, so `pear stage $(npm pkg get upgrade)` works (`npm pkg get` prints a quoted JSON string), and `npm pkg set upgrade=$(pear touch)` stores a new link; earlier releases reject a quoted link with `A valid pear link must be specified.`
- From 3.6.0 the human-readable output of `pear build`, `cores`, `dump`, `gc`, `info`, `provision`, `stage`, and `versions` wraps pear links in green ANSI codes on macOS and Linux, even when piped and with `NO_COLOR` set. From 3.7.0 `pear info` is the exception: it colors its output only when stdin is a terminal. Script against `--json`, which carries no color.
- An unknown argument fails with `Unexpected argument  '<value>'` (two spaces before the quote) from 3.6.0, and with `Unrecognized Argument at index <n> with value <value>` before.
- `pear sidecar inspect` was removed in 3.7.0 with no replacement; it now fails with `Unexpected argument  'inspect'`. `pear dump <link>` takes only a `pear://` link or verlink; a `file:` URL or local directory path fails with `A valid pear link must be specified.` (it already did on 3.6.0, whose help text said otherwise, though 3.6.0 checked `<dir>` first, so a non-empty `<dir>` without `--force` failed with `Dir is not empty. To overwrite: --force`).
- From 3.7.0 `pear --menu` groups commands into Ship, Install & inspect, Release, Network, and a collapsed Platform group.
- There is no `pear dev` command, and `pear run` no longer launches an app — apps now embed the `pear-runtime` (Pear OTA) library directly instead of being launched by the CLI.
