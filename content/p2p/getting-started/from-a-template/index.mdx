The fastest way to a production-shaped app is to copy an official starter project—a boilerplate you clone and change—and learn where each piece lives. Every template embeds a `pear-runtime`-family module for peer-to-peer over-the-air updates—pick the one that matches what you're shipping.

## Which one?

- **Building a desktop GUI?** Start from [hello-pear-electron](/p2p/getting-started/from-a-template/start-from-hello-pear-electron)—it ships a renderer and the preload bridge that connects your UI to peer-to-peer logic in a Bare worker.
- **Building a long-running headless program—a service, REPL, or TUI?** Start from [hello-pear-bare](/p2p/getting-started/from-a-template/start-from-hello-pear-bare)—it compiles to a single standalone binary per OS and architecture and keeps your peer-to-peer code in a Bare worker.
- **Building a short-lived CLI that runs and exits?** Start from [hello-pear-daemon](/p2p/getting-started/from-a-template/start-from-hello-pear-daemon)—the same standalone binary, but the update check runs in a detached daemon so the command never blocks on the network.
- **Building a terminal app that runs an AI model on the user's machine?** Start from [hello-pear-qvac-tui](/p2p/getting-started/from-a-template/start-from-hello-pear-qvac-tui)—it adds a [QVAC](https://qvac.tether.io) inference worker and a `bare-tui` interface to the hello-pear-bare shape.
- **Building a mobile app?** Start from [hello-pear-react-native](/p2p/getting-started/from-a-template/start-from-hello-pear-react-native)—it embeds a Bare worklet in an Expo/React Native app via [`pear-mobile`](/pear/reference/pear/mobile).

They share the same peer-to-peer core: the [Bare](/bare/reference/bare/modules) runtime, a `pear-runtime`-family module for updates ([`pear-runtime`](/pear/reference/pear/runtime) on desktop and in the terminal, [`pear-mobile`](/pear/reference/pear/mobile) on mobile), and the [Hyperswarm](/p2p/reference/building-blocks/hyperswarm) + [Corestore](/p2p/reference/helpers/corestore) stack. In the worker-based templates—hello-pear-electron, hello-pear-bare, hello-pear-qvac-tui, and hello-pear-react-native—your peer-to-peer logic is portable and only the shell (GUI, terminal, or mobile) changes. hello-pear-daemon has no worker, so its only peer-to-peer code is the update client. See [Runtime and languages](/pear/explanation/runtime-and-languages).

<Callout type="info">
Once you've cloned a template and made it yours, ship it over the air. For desktop and terminal, [Deploy your application](/pear/how-to/operate-an-app/manual-deployment/deployment) is the step-by-step release flow, and [Release pipeline](/pear/explanation/deployment-releasing-apps-p2p) explains the stage → provision → multisig model behind it. Mobile shares that stage/provision/multisig model but builds a different payload—see [Deploy your mobile application](/pear/how-to/operate-an-app/manual-deployment/mobile).
</Callout>
