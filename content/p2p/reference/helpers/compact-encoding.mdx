<Status level="stable" />

`compact-encoding` packages small binary codecs behind a shared encoder interface. It is commonly paired with [Protomux](/p2p/reference/helpers/protomux) message schemas and shows up in [Hypercore](/p2p/reference/building-blocks/hypercore) and other Holepunch protocol surfaces whenever structured binary payloads matter. For the upstream package and implementation details, see the [compact-encoding repository](https://github.com/holepunchto/compact-encoding).

## Module-level encode and decode helpers

#### `const buffer = cenc.encode(enc, value)`

Encodes a single `value` using `enc` into a freshly allocated `Buffer` and returns it. Equivalent to manually creating a state, calling `enc.preencode` and `enc.encode`, and slicing the buffer — useful when you just want bytes back in one step.

| Param | Type | Description |
| --- | --- | --- |
| `enc` | `object` | Any compact-encoding encoder (for example `cenc.uint`, a custom encoder). |
| `value` | `*` | The value to encode. |

- Returns: `Buffer`

```js
const buf = cenc.encode(cenc.uint, 42)
// <Buffer 2a>
```

#### `const value = cenc.decode(enc, buffer)`

Decodes a single value from `buffer` using `enc`. Equivalent to constructing a state from the buffer and calling `enc.decode`.

| Param | Type | Description |
| --- | --- | --- |
| `enc` | `object` | Any compact-encoding encoder. |
| `buffer` | `Buffer` | The buffer to decode from. |

- Returns: The decoded value.

```js
const val = cenc.decode(cenc.uint, buf) // 42
```

## Install

```sh
npm i compact-encoding
```

The package ships TypeScript declarations and an `exports` map. Besides the main entry it exposes `compact-encoding/raw` (the same object as `cenc.raw`), `compact-encoding/lexint` (the same codec as `cenc.lexint`) and `compact-encoding/endian` (the host byte order flags `LE` and `BE`), each with its own `.d.ts`. Any other deep import is refused by the map.

## Quickstart

```js
import cenc from 'compact-encoding'

const state = cenc.state()

cenc.uint.preencode(state, 42)
cenc.string.preencode(state, 'hello')

state.buffer = Buffer.allocUnsafe(state.end)
state.start = 0

cenc.uint.encode(state, 42)
cenc.string.encode(state, 'hello')

state.start = 0

console.log(cenc.uint.decode(state))
console.log(cenc.string.decode(state))
```

## API Reference

### Encoder contract

Every bundled encoder follows the same three-method contract. The top-level helpers and exported factories below all return or consume objects with this shape.

#### `enc.preencode(state, val)`

Does a fast preencode dry-run that only sets state.end. Use this to figure out how big of a buffer you need.

`preencode` is not guaranteed to reject an invalid `val`; `encode` is where a value is checked. Most codecs refuse a bad value in `encode` only, so call `encode` (or [`cenc.encode`](#const-buffer--cencencodeenc-value)) before trusting a value.

#### `enc.encode(state, val)`

Writes the encoded form of the value into `state.buffer` at `state.start` (the buffer must have been preallocated via `preencode`), advancing `state.start` past the written bytes.

| Parameter | Type | Description |
| --- | --- | --- |
| `state` | `object` | A compact-encoding state with `start`, `end`, and `buffer`. |
| `val` | `*` | The value to encode. |

- Returns: `undefined` — the encoded bytes are written into `state.buffer` in place.
- Throws: a `TypeError` or `RangeError` when `val` is not valid for the codec (see [Value validation](#value-validation)).

```js
const cenc = require('compact-encoding')
const state = cenc.state()
cenc.uint.preencode(state, 42)
state.buffer = Buffer.allocUnsafe(state.end)
cenc.uint.encode(state, 42)
// state.buffer is a 1-byte Buffer containing the encoded uint
```

#### `val = enc.decode(state)`

Reads and returns a value from `state.buffer` at `state.start`, advancing `state.start` past the decoded value.

| Parameter | Type | Description |
| --- | --- | --- |
| `state` | `object` | A compact-encoding state with `start`, `end`, and `buffer`. |

- Returns: `*` — The decoded value.

```js
const cenc = require('compact-encoding')
const buf = cenc.encode(cenc.bool, true)
const state = cenc.state(0, buf.byteLength, buf)
const val = cenc.bool.decode(state) // true
```

### State and convenience helpers

#### `cenc.state(start = 0, end = 0, buffer = null)`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L10)

A mutable state object `{ start, end, buffer }` used by all encoders.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `start` | `number` | `0` | Initial read/write offset. |
| `end` | `number` | `0` | Initial end offset (set by preencode to determine required buffer size). |
| `buffer` | [`Buffer\|Uint8Array\|null`](https://nodejs.org/api/buffer.html#class-buffer) | `null` | Underlying buffer; allocate after preencoding. |

- Returns: [`State`](#state) — A new state object `{ start, end, buffer }`.

```js
const cenc = require('compact-encoding')
const state = cenc.state()
cenc.uint.preencode(state, 42)
cenc.string.preencode(state, 'hi')
state.buffer = Buffer.allocUnsafe(state.end)
cenc.uint.encode(state, 42)
cenc.string.encode(state, 'hi')
```

#### `cenc.from(enc)`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L1555)

Coerces `enc` — an existing compact encoder, a named raw string encoding such as `'utf8'` or `'json'`, a codec with `encode`/`decode`, or an abstract encoding with `encodingLength` — into a compact-encoding-compatible encoder object.

| Parameter | Type | Description |
| --- | --- | --- |
| `enc` | `string\|object` | An encoding name, compact encoder, abstract-encoding, or codec. |

- Returns: `object` — A compact-encoding encoder with `preencode`, `encode`, and `decode`.

```js
const cenc = require('compact-encoding')
const enc = cenc.from('utf-8')
const buf = cenc.encode(enc, 'hello')
const val = cenc.decode(enc, buf) // 'hello'
```

### Encoder factories

#### `cenc.fixed(n)`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L1091)

An encoder for fixed-size buffers, where `n` is the exact byte length every encoded value must have.

| Parameter | Type | Description |
| --- | --- | --- |
| `n` | `number` | Exact number of bytes to encode/decode. |

- Returns: `object` — An encoder that reads and writes exactly `n` bytes.

```js
const cenc = require('compact-encoding')
const enc = cenc.fixed(4)
const buf = cenc.encode(enc, Buffer.alloc(4, 0xff))
const val = cenc.decode(enc, buf) // <Buffer ff ff ff ff>
```

#### `cenc.array(enc)`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L1114)

An encoder that prefixes arrays with their length and encodes each item in order using `enc`.

| Parameter | Type | Description |
| --- | --- | --- |
| `enc` | `object` | An encoder with `preencode`, `encode`, and `decode` methods. |

- Returns: `object` — An encoder for arrays of values handled by `enc`.

```js
const cenc = require('compact-encoding')
const enc = cenc.array(cenc.uint)
const buf = cenc.encode(enc, [1, 2, 3])
const val = cenc.decode(enc, buf) // [1, 2, 3]
```

#### `cenc.frame(enc)`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L1140)

An encoder that prefixes one encoded payload with its byte length. Decoding throws `Out of bounds` when the byte-length prefix is longer than the bytes left in the buffer. Before 3.5.2 it decoded whatever bytes remained.

| Parameter | Type | Description |
| --- | --- | --- |
| `enc` | `object` | An encoder with `preencode`, `encode`, and `decode` methods. |

- Returns: `object` — An encoder that wraps each value in a byte-length frame.

```js
const cenc = require('compact-encoding')
const enc = cenc.frame(cenc.string)
const buf = cenc.encode(enc, 'hello')
const val = cenc.decode(enc, buf) // 'hello'
```

#### `cenc.record(keyEncoding, valueEncoding)`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L1468)

An encoder for plain object records, with `keyEncoding` for object keys and `valueEncoding` for object values. Keys are always strings, so `keyEncoding` has to be a string encoding. The record is prefixed with its number of pairs. The order the pairs are written in is undefined, so two encoders can write the same record as different bytes; use [`cenc.orderedRecord`](#cencorderedrecordkeyencoding-valueencoding) when the bytes must be stable.

| Parameter | Type | Description |
| --- | --- | --- |
| `keyEncoding` | `object` | Encoder used for each object key. |
| `valueEncoding` | `object` | Encoder used for each object value. |

- Returns: `object` — An encoder that reads/writes plain objects as key-value pairs.

```js
const cenc = require('compact-encoding')
const enc = cenc.record(cenc.string, cenc.uint)
const buf = cenc.encode(enc, { a: 1, b: 2 })
const val = cenc.decode(enc, buf) // [Object: null prototype] { a: 1, b: 2 }
```

#### `cenc.orderedRecord(keyEncoding, valueEncoding)`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L1497)

Same as [`cenc.record`](#cencrecordkeyencoding-valueencoding), but the keys are sorted before they are written, so a record encodes to the same bytes whatever order its keys were set in. Keys sort by their own UTF-8 bytes rather than by what `keyEncoding` writes, a comparison every language can reproduce. Keys that encode to the same bytes, two different unpaired surrogates for example, keep the order they were set in. Decoding is the same as `cenc.record`. Added in 3.6.0.

| Parameter | Type | Description |
| --- | --- | --- |
| `keyEncoding` | `object` | String encoder used for each object key. |
| `valueEncoding` | `object` | Encoder used for each object value. |

- Returns: `object` — An encoder that reads plain objects and writes them with sorted keys.

```js
const cenc = require('compact-encoding')
const enc = cenc.orderedRecord(cenc.string, cenc.uint)
const a = cenc.encode(enc, { b: 2, a: 1 })
const b = cenc.encode(enc, { a: 1, b: 2 })
a.equals(b) // true
```

#### `cenc.stringRecord`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L1526)

A prebuilt `record(cenc.string, cenc.string)` encoder for simple string maps. `cenc.orderedStringRecord` is the same with sorted keys, built on `orderedRecord`.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const buf = cenc.encode(cenc.stringRecord, { name: 'alice', role: 'admin' })
const val = cenc.decode(cenc.stringRecord, buf) // [Object: null prototype] { name: 'alice', role: 'admin' }
```

### Numeric encodings

#### `cenc.uint64`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L264)

Unsigned integer encoders (`cenc.uint`, `cenc.uint8`, `cenc.uint16`, `cenc.uint24`, `cenc.uint32`, `cenc.uint40`, `cenc.uint48`, `cenc.uint56`, `cenc.uint64`). `cenc.uint` chooses a compact size automatically; the fixed-width variants always use the named byte width.

Big-endian variants (`cenc.uintbe`, `cenc.uint16be`, `cenc.uint32be`, `cenc.uint64be`) write each multi-byte body most-significant byte first, so they are not interchangeable with the little-endian codecs on the wire. `cenc.uintbe` keeps the same one-byte size prefix as `cenc.uint`. `cenc.uintbe` and `cenc.uint16be` are new in 3.7.0; `cenc.uint32be` and `cenc.uint64be` predate it.

JavaScript numbers are exact only up to `Number.MAX_SAFE_INTEGER`, so `cenc.uint64` and the other number codecs stop there. For the full 64-bit range use `cenc.biguint64`, which writes the same bytes.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const buf = cenc.encode(cenc.uint64, 2 ** 32)
const val = cenc.decode(cenc.uint64, buf) // 4294967296
```

#### `cenc.int64`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L571)

Signed integer encoders (`cenc.int`, `cenc.int8` … `cenc.int64`) built on top of the unsigned variants with ZigZag encoding.

ZigZag doubles a value's magnitude before writing it as an unsigned integer, so a signed integer only reaches half as far as an unsigned one of the same width. Since 3.3.1 the signed codecs validate that range explicitly and reject anything outside `-(2**52)` to `2**52 - 1`; use `cenc.bigint` for larger values. Earlier releases silently lost precision instead.

Big-endian variants (`cenc.intbe`, `cenc.int16be`, `cenc.int32be`, `cenc.int64be`) are the matching unsigned big-endian codec with ZigZag encoding. They are new in 3.7.0. Each fixed-width signed codec also inherits the width of its unsigned codec, so `cenc.int8` only accepts -128 to 127.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const buf = cenc.encode(cenc.int64, -4294967296)
const val = cenc.decode(cenc.int64, buf) // -4294967296
```

#### `cenc.bigint`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L689)

BigInt-aware integer encoders (`cenc.biguint64`, `cenc.bigint64`, `cenc.biguint`, `cenc.bigint`) for fixed-width or variable-width large integer values. `cenc.biguint64` and `cenc.bigint64` write the same bytes as `cenc.uint64` and `cenc.int64` and carry the whole 64-bit range, which those cannot. Since 3.6.0 `cenc.biguint` refuses a negative value and the 64-bit codecs refuse a value outside their width, both with a `RangeError`.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const buf = cenc.encode(cenc.bigint, -(2n ** 128n))
const val = cenc.decode(cenc.bigint, buf) // -340282366920938463463374607431768211456n
```

#### `cenc.float64`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L733)

Floating-point encoders (`cenc.float32`, `cenc.float64`) using IEEE-754 little-endian layouts. Since 3.7.0 `encode` throws a `TypeError` for anything that is not a `number`; `NaN` and the infinities are still accepted.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const buf = cenc.encode(cenc.float64, Math.PI)
const val = cenc.decode(cenc.float64, buf) // 3.141592653589793
```

#### `cenc.lexint`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L701)

The lexicographic integer encoder exported from the `./lexint` module. Encoded values sort byte-wise in the same order as the numbers. Since 3.6.0 it throws a `RangeError` for a negative number, `NaN`, or an infinite value, in both `preencode` and `encode`.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const buf = cenc.encode(cenc.lexint, 1000)
const val = cenc.decode(cenc.lexint, buf) // 1000
```

### Binary, buffer, and typed-array encodings

#### `cenc.binary`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L802)

Buffer-oriented encoders. `buffer` length-prefixes a byte sequence and decodes a zero length as an empty buffer. `optionalBuffer` is like `buffer` but also accepts `null`; an empty buffer and `null` both encode as length 0, and that length decodes as `null`. `binary` accepts either a string or buffer-like input.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const buf = cenc.encode(cenc.binary, 'hello')
const val = cenc.decode(cenc.binary, buf) // <Buffer 68 65 6c 6c 6f>
```

#### `cenc.arraybuffer`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L814)

An encoder for `ArrayBuffer` instances. Decoding throws `Out of bounds` when the length prefix is longer than the bytes left in the buffer. Before 3.5.2 it returned a zero-padded `ArrayBuffer`.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const ab = new ArrayBuffer(4)
const buf = cenc.encode(cenc.arraybuffer, ab)
const val = cenc.decode(cenc.arraybuffer, buf) // ArrayBuffer { byteLength: 4 }
```

#### `cenc.float64array`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L916)

Length-prefixed typed-array encoders (`cenc.uint8array`, `cenc.uint16array`, `cenc.uint32array`, `cenc.int8array`, `cenc.int16array`, `cenc.int32array`, `cenc.biguint64array`, `cenc.bigint64array`, `cenc.float32array`, `cenc.float64array`) that preserve the underlying element type.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const buf = cenc.encode(cenc.float64array, new Float64Array([Math.PI]))
const val = cenc.decode(cenc.float64array, buf) // Float64Array [3.141592653589793]
```

#### `cenc.fixed64`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L1112)

Prebuilt fixed-size buffer encoders — `cenc.fixed8`, `cenc.fixed16`, `cenc.fixed24`, `cenc.fixed32`, and `cenc.fixed64` — for 8, 16, 24, 32, and 64-byte values.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const sig = Buffer.alloc(64)
const buf = cenc.encode(cenc.fixed64, sig)
const val = cenc.decode(cenc.fixed64, buf) // <Buffer 00 00 ... (64 bytes)>
```

### Network encodings

#### `cenc.port`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L1301)

The same encoder as `cenc.uint16`, provided for protocol readability when encoding network ports.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const buf = cenc.encode(cenc.port, 8080)
const val = cenc.decode(cenc.port, buf) // 8080
```

#### `cenc.ip`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L1429)

Encoders for IPv4 addresses, IPv6 addresses, or either family with an embedded family tag (`cenc.ipv4`, `cenc.ipv6`, `cenc.ip`). Since 3.6.0 `encode` throws a `RangeError` for an address that does not have 4 parts (IPv4) or 8 parts (IPv6, where `::` stands for the missing zero parts), or whose part is larger than 255 (IPv4) or `0xffff` (IPv6). Earlier releases wrote whatever bytes the parser produced.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const buf4 = cenc.encode(cenc.ip, '1.2.3.4')
cenc.decode(cenc.ip, buf4) // '1.2.3.4'
const buf6 = cenc.encode(cenc.ip, '::1')
cenc.decode(cenc.ip, buf6) // '0:0:0:0:0:0:0:1'
```

#### `cenc.ipAddress`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L1449)

Address-object encoders (`cenc.ipv4Address`, `cenc.ipv6Address`, `cenc.ipAddress`) for `{ host, family?, port }` shapes.

- Returns: `object`

```js
const cenc = require('compact-encoding')
const buf = cenc.encode(cenc.ipAddress, { host: '1.2.3.4', port: 8080 })
const val = cenc.decode(cenc.ipAddress, buf) // { host: '1.2.3.4', family: 4, port: 8080 }
```

### Raw variants

#### `cenc.raw`

[src](https://github.com/holepunchto/compact-encoding/blob/v3.7.1/index.js#L14)

A namespace of non-length-prefixed variants for many buffer, string, array, JSON, and typed-array encodings such as `cenc.raw.buffer`, `cenc.raw.utf8`, `cenc.raw.array(enc)`, and `cenc.raw.json`. A raw decoder consumes everything up to `state.end`. Since 3.6.0 it stops at `state.end` rather than the end of `state.buffer`, so a raw codec nested in [`cenc.frame`](#cencframeenc) reads only its own frame.

- Returns: `object`

```js
const cenc = require('compact-encoding')
// copy raw bytes into state
const buf = Buffer.from([1, 2, 3])
const state = cenc.state()
cenc.raw.preencode(state, buf)
state.buffer = Buffer.allocUnsafe(state.end)
cenc.raw.encode(state, buf)
```

### Complete codec reference

The sections above detail the contract and the most common encoders. Below is the full catalog of bundled codecs shipped by compact-encoding v3.7.1. Every entry is an object implementing the [encoder contract](#encoder-contract) (`preencode` / `encode` / `decode`), so any of them can be composed with [`cenc.array(enc)`](#cencarrayenc), [`cenc.frame(enc)`](#cencframeenc), or used directly with [`cenc.encode`](#const-buffer--cencencodeenc-value) / [`cenc.decode`](#const-value--cencdecodeenc-buffer). Fixed-size integers are little-endian unless the name ends in `be`.

**Unsigned integers**

| Codec | Bytes | Notes |
| --- | --- | --- |
| `cenc.uint` | 1–9 | Smallest fixed-size encoding with a prefix signalling which; best for values spanning a wide range. |
| `cenc.uintbe` | 1–9 | Like `cenc.uint` with big-endian bodies. |
| `cenc.uint8` | 1 | Fixed `uint8`. |
| `cenc.uint16` | 2 | Fixed `uint16`; useful for ports. |
| `cenc.uint16be` | 2 | Big-endian `uint16`. |
| `cenc.uint24` | 3 | Fixed `uint24`; useful for message framing. |
| `cenc.uint32` | 4 | Fixed `uint32`; useful for large message framing. |

## Value validation

Since 3.6.0 `encode` rejects values a codec cannot represent instead of writing wrong bytes. The thrown error is a `TypeError` for a wrong kind of value and a `RangeError` for a value outside the codec's range. These errors replace the plain `Error` that earlier releases threw for integer ranges.

| Codec | Throws |
| --- | --- |
| `cenc.uint`, `cenc.uint56`, `cenc.uint64`, and the `be` variants of them | `TypeError` for a non-integer. `RangeError` outside 0 to `Number.MAX_SAFE_INTEGER`. Decoding a stored value above that limit also throws a `RangeError`. |
| `cenc.uint8`, `cenc.uint16`, `cenc.uint24`, `cenc.uint32`, `cenc.uint40`, `cenc.uint48`, `cenc.uint16be`, `cenc.uint32be` | `TypeError` for a non-integer. `RangeError` outside 0 to the width's maximum, for example 255 for `uint8`. |
| `cenc.int` and the fixed-width signed codecs | `TypeError` for a non-integer. `RangeError` outside `-(2**52)` to `2**52 - 1`, or outside the unsigned width after ZigZag. |
| `cenc.biguint`, `cenc.bigint` | `RangeError` for a negative `biguint`. |
| `cenc.biguint64`, `cenc.bigint64` | `RangeError` outside the 64-bit range. |
| `cenc.float32`, `cenc.float64` | `TypeError` for a non-number (3.7.0). |
| `cenc.lexint` | `RangeError` for a negative, `NaN` or infinite number. |
| `cenc.ipv4`, `cenc.ipv6`, `cenc.ip` | `RangeError` for a wrong part count or an out-of-range part. |
| `cenc.fixed(n)` | `Error('Incorrect buffer size')` unless the value is exactly `n` bytes. |

Since 3.7.0 the error for `cenc.uint` and `cenc.uint64` names the wider codec to switch to, such as `uint must be between 0 and 9007199254740991, use biguint`; `cenc.int` and `cenc.int64` do the same with `bigint` and `bigint64`. Decoding a truncated buffer still throws `Error('Out of bounds')`.

Code that passed `undefined`, a float or an out-of-range number to an integer codec, a non-number to a float codec, or an IP string with the wrong number of parts or an oversized part to an IP codec, now throws at `encode` time instead of producing bytes. Check values before they reach the encoder.
