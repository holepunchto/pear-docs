<Status level="stable" />

`Corestore` manages many related [Hypercores](/p2p/reference/building-blocks/hypercore) behind one storage root and one replication surface. It is the helper you usually share across [Hyperbee](/p2p/reference/building-blocks/hyperbee), [Hyperdrive](/p2p/reference/building-blocks/hyperdrive), and [Autobase](/p2p/reference/building-blocks/autobase) instances. For upstream source and changelog context, see the [Corestore repository](https://github.com/holepunchto/corestore).

## Install

```sh
npm i corestore
```

## Quickstart

```js
import Corestore from 'corestore'

const store = new Corestore('./app-storage')
await store.ready()

const messages = store.get({
  name: 'messages',
  valueEncoding: 'json'
})

await messages.ready()
await messages.append({ text: 'hello from corestore' })

console.log(await messages.get(0))

await store.close()
```

## API Reference

### Constructor and lifecycle

#### `new Corestore(storage, options = {})`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L237)

Create a new Corestore instance.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `storage` | `string\|object` | — | can be either a `hypercore-storage` instance or a string. |
| `options` | [`CorestoreOptions`](#corestoreoptions) | `{}` | Store options. |

- Throws: `ERR_ASSERTION` if `primaryKey` is set on a root store without `unsafe: true`.

#### `await store.ready()`

A promise that resolves once the storage seed is loaded and properties such as `store.primaryKey` are available.

#### `await store.close()`

Fully close this Corestore instance.

#### `await store.suspend([options])`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L354)

Suspend the underlying storage for the Corestore.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `options` | `object` | `{}` | Suspend options. |

- Returns: [`Promise<void>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) — Resolves once the storage is suspended.

Since 7.12.0 this no longer flushes the database first. Earlier releases flushed on every `suspend()` unless the store was read-only; flush explicitly if you were relying on that.

```js
await store.suspend()
```

#### `await store.resume()`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L361)

Resume a suspended Corestore.

- Returns: [`Promise<void>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) — Resolves once the storage is resumed.

```js
await store.resume()
```

### Store properties

#### `store.storage`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L241)

The backing storage adapter used for aliases, seeds, and Hypercore data files.

- Returns: `object`

#### `store.primaryKey`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L256)

The 32-byte primary key used to deterministically derive writable named cores and namespaced key pairs.

- Returns: [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer)

#### `store.readOnly`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L254)

`true` when the store was opened without write access.

- Returns: `boolean`

#### `store.manifestVersion`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L258)

The Hypercore manifest version used when Corestore creates new writable cores. Set it with the [`manifestVersion` option](#corestoreoptions), or override it for a single core with [`store.get()`](#storegetkey---name-a-name-hypercoreopts).

- Returns: `number`

#### `store.alwaysLatestBlock`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L261)

`true` when every core this store loads asks for the latest block with each upgrade request. Set it with the [`alwaysLatestBlock` option](#corestoreoptions). Sessions and namespaces created from a store share its value.

- Returns: `boolean`

#### `store.active`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L260)

`true` when the store should automatically attach loaded cores to active replication streams.

- Returns: `boolean`

#### `store.opened` / `store.closed`

`true` once [`store.ready()`](#await-storeready) has resolved / once [`store.close()`](#await-storeclose) has completed. Useful for guarding access to a store whose lifecycle you don't fully control.

- Returns: `boolean`

### Loading cores and scoping sessions

#### `store.get(key | { name: 'a-name', ...hypercoreOpts})`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L602)

Loads a Hypercore, either by name (if the `name` option is provided), or from the provided key (if the first argument is a Buffer or String with hex/z32 key, or if the `key` options is set).

| Parameter | Type | Description |
| --- | --- | --- |
| `opts` | [`Buffer\|string\|object`](https://nodejs.org/api/buffer.html#class-buffer) | A key (Buffer/hex/z32 string), or an options object with `name`, `key`, or `discoveryKey` plus Hypercore options. |

- Returns: [`Hypercore`](/p2p/reference/building-blocks/hypercore) — A Hypercore session for the requested core.

`allowLatestBlock` is forwarded through to the returned Hypercore's own [`allowLatestBlock` option](/p2p/reference/building-blocks/hypercore#hypercoreoptions). When you set it, even to `false`, it takes precedence over the store's [`alwaysLatestBlock`](#storealwayslatestblock).

When `get()` creates a new writable core, from `name` or `keyPair`, you can pass `manifestVersion` to override [`store.manifestVersion`](#storemanifestversion) for that call. A core that already exists under that name keeps the manifest it was created with. Added in 7.12.6.

`userData` is an object of keys and values that `get()` writes to the core's local User Data store, as the Hypercore [`userData` option](/p2p/reference/building-blocks/hypercore#new-hypercorestorage-key-options) does. Added in 7.14.0. `weak` is forwarded like the Hypercore [`weak` option](/p2p/reference/building-blocks/hypercore#hypercoreoptions), so the session does not keep the core alive and does not stop [`store.purge()`](#await-storepurgekeys-options). Added in 7.15.0.

```js
const core = store.get({ name: 'my-core' })
```

#### `storeA.session()`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L365)

Create a new Corestore session. Closing a session will close all cores made from this session.

| Parameter | Type | Description |
| --- | --- | --- |
| `opts` | `object` | Session options (forwarded to the new Corestore). |

- Returns: [`Corestore`](/p2p/reference/helpers/corestore) — A new Corestore session sharing the same storage.

```js
const session = store.session()
```

#### `store.namespace(name)`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L375)

Create a new namespaced Corestore session. Namespacing is useful if you're going to be sharing a single Corestore instance between many applications or components, as it prevents name collisions.

| Parameter | Type | Description |
| --- | --- | --- |
| `name` | [`string\|Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | Namespace name; combined with the current namespace to derive a new one. |
| `opts` | `object` | Session options (forwarded to the new Corestore). |

- Returns: [`Corestore`](/p2p/reference/helpers/corestore) — A new namespaced Corestore session.

```js
const ns1 = store.namespace('a')
const ns2 = ns1.namespace('b')
const core1 = ns1.get({ name: 'main' }) // These will load different Hypercores
const core2 = ns2.get({ name: 'main' })
```

### Replication and discovery

#### `store.replicate(optsOrStream)`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L515)

Creates a replication stream that's capable of replicating all Hypercores that are managed by the Corestore, assuming the remote peer has the correct capabilities.

| Parameter | Type | Description |
| --- | --- | --- |
| `isInitiator` | [`boolean\|Stream`](https://nodejs.org/api/stream.html) | `true`/`false` to initiate, or an existing stream/connection to replicate over. |
| `opts` | `object` | Replication options, forwarded to the protocol stream. |

- Returns: [`Stream`](https://nodejs.org/api/stream.html) — The replication stream.

```js
const swarm = new Hyperswarm()

// join the relevant topic
swarm.join(...)

// simply pass the connection stream to corestore
swarm.on('connection', (connection) => store.replicate(connection))
```

#### `store.findingPeers()`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L339)

A completion callback. Call it after the current peer-discovery pass finishes so pending update waits on loaded cores can unblock.

- Returns: `Function` — A `done` function to call once peer discovery has finished.

```js
const done = store.findingPeers()
swarm.flush().then(done, done)
```

#### `store.list(namespace)`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L382)

Creates a discovery key stream of all cores within a namespace or all cores in general if no namespace is provided.

| Parameter | Type | Description |
| --- | --- | --- |
| `namespace` | [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | to scope to; omit to list all cores. |

- Returns: [`Readable`](https://nodejs.org/api/stream.html#class-streamreadable) — A stream of discovery keys.

```js
for await (const discoveryKey of store.list()) console.log(discoveryKey)
```

#### `store.getAuth(discoveryKey)`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L386)

The storage-layer auth metadata for that core, including manifest details when available.

| Parameter | Type | Description |
| --- | --- | --- |
| `discoveryKey` | [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | Discovery key of the core to look up. |

- Returns: [`Promise<object\|null>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) — The auth record, or `null` if not stored.

```js
const auth = await store.getAuth(discoveryKey)
```

### Key derivation and maintenance

#### `await store.createKeyPair(name, ns = this.ns)`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L662)

Generate a key pair seeded with the Corestore's primary key using a `name` and a `ns` aka namespace. `ns` defaults to the current namespace.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | `string` | — | to derive the key pair from. |
| `ns` | [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | `this.ns` | — |

- Returns: [`Promise<{publicKey: Buffer, secretKey: Buffer}>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) — The derived key pair.

```js
const keyPair = await store.createKeyPair('signer')
```

#### `store.audit(opts = {})`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L350)

An audit report describing the state of the backing store and any detected inconsistencies.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `opts` | `object` | `{}` | Audit options (for example `dryRun`). |

- Returns: `AsyncGenerator<object>` — Yields a result per core as it is audited.

```js
for await (const report of store.audit()) console.log(report)
```

#### `await store.staticify(core, opts = {})`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L554)

A reopened Hypercore whose manifest is converted into a static prologue-based manifest for the current data snapshot.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `core` | [`Hypercore`](/p2p/reference/building-blocks/hypercore) | — | The source core to snapshot. Must have data. |
| `opts` | `object` | `{}` | Options forwarded to `store.get()` for the new core. `key` and `name` are ignored, because the static core's key comes from its manifest. |

| Option | Default | Description |
| --- | --- | --- |
| `manifest` | — | Manifest fields that replace the defaults of the static manifest, for example `version` or `userData`. The defaults are `version` 1, the source core's `hash`, a `quorum` of 0, no `signers`, and a `prologue` that covers the source core's current length. The new core's key is the key of the resulting manifest. Added in 7.16.0. |

- Returns: [`Promise<Hypercore>`](/p2p/reference/building-blocks/hypercore) — The new static Hypercore.
- Throws: if the core has no data to staticify.

```js
const staticCore = await store.staticify(core)

// Give the static core a version 2 manifest that carries user data
const custom = await store.staticify(core, {
  manifest: { version: 2, userData: Buffer.from('mapped from somewhere') }
})
```

#### `await store.purge(keys, [options])`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L390)

Permanently delete cores from the store's storage, using [`core.purge()`](/p2p/reference/building-blocks/hypercore#await-corepurge) for each one. A core the store does not hold is skipped, and so is a core with an open session unless you pass `force`. Weak sessions do not count as open. Added in 7.15.0.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `keys` | `Array<Buffer\|string\|object>\|Buffer\|string\|object` | — | The cores to purge, one entry or an array. An entry is a core key as a Buffer or a hex/z32 string, or an object with a `key` or a `discoveryKey`, such as a Hypercore. |
| `options` | `object` | `{}` | Purge options. |

| Option | Default | Description |
| --- | --- | --- |
| `force` | `false` | Purge cores that have open sessions too. Their sessions are closed first, including sessions made through [`store.session()`](#storeasession) and [`store.namespace()`](#storenamespacename) of the same store. |

- Returns: [`Promise<Buffer[]>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) — The discovery keys of the cores that were purged, in the order of `keys`. Skipped cores are left out.

A purged name starts over the next time you call [`store.get({ name })`](#storegetkey---name-a-name-hypercoreopts): it opens an empty core with the same key, unless you pass a different `manifestVersion`.

```js
const core = store.get({ name: 'drafts' })
await core.append('hello')

const key = core.key
await core.close() // purge skips cores with open sessions

const purged = await store.purge(key) // or an array of keys
console.log(purged.length) // 1
```

### Watchers

#### `store.watch((core) => {})`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L281)

Register a callback called when new Hypercores are opened. `core` is the internal core for the opened Hypercore. It can be used to create weak references to a Hypercore like so:

| Parameter | Type | Description |
| --- | --- | --- |
| `fn` | `Function` | Callback invoked with the internal `core` each time a Hypercore is opened. |

- Returns: `void`

```js
store.watch(function (core) {
  const weakCore = new Hypercore({ core, weak: true })
})
```

#### `store.unwatch(callback)`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L290)

Unregister a callback used with `store.watch(callback)` so it no longer fires.

| Parameter | Type | Description |
| --- | --- | --- |
| `callback` | `Function` | The callback previously passed to `store.watch()`. |

- Returns: `void`

```js
store.unwatch(onCore)
```

### Group notifications (experimental)

#### `store.notifyGroup(topic)`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L310)

Get a `handle` for updates from all `hypercore`s with the group `topic` set.

| Parameter | Type | Description |
| --- | --- | --- |
| `topic` | [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | The 32-byte group topic to watch. |

- Returns: [`GroupNotifyHandle`](/p2p/reference/helpers/corestore) — A handle that emits `update` when a core in the group changes.

```js
const handle = store.notifyGroup(topic)
handle.on('update', () => console.log('group changed'))
```

<Callout type="warn">
Group notifications are experimental. The API is subject to change and may break in any release.
</Callout>

#### `handle.updates(opts = {})`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/lib/notify.js#L12)

Gets updates for the `topic` the handle is for.

| Parameter | Default |
| --- | --- |
| `opts` | `{}` |

| Option | Default | Description |
| --- | --- | --- |
| `since` | `0` | What timestamp to start returning updates from. Default `0` returns all updates |
| `reverse` | `true` | Flag to return updates in reverse order. Defaults to `true` so latest returned first |

- Returns: [`Readable`](https://nodejs.org/api/stream.html#class-streamreadable) — A stream of the keys of the cores that updated.

```js
for await (const key of handle.updates()) {
  // ...
}
```

#### `handle.destroy()`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/lib/notify.js#L20)

Destroys and unregisters the `handle` from its `store`.

#### `handle.on('update', callback)`

Calls the callback whenever a core with the `topic` for the `handle` updates.

#### `store.on('group-active', (topic) => {})`

[src](https://github.com/holepunchto/corestore/blob/v7.16.1/index.js#L302)

The `group-active` event emits whenever an opened Hypercore in the store updates. The `topic` is the group topic the core belongs to.

## Types

### CorestoreOptions

Options for the \{@link Corestore\} constructor. Any other options are forwarded
to the underlying `hypercore-storage` instance.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `primaryKey` | [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | — | The 32-byte master key from which all writable named cores are derived. Generated and persisted automatically when omitted. |
| `writable` | `boolean` | `true` | Set to `false` to open the store read-only; loaded cores default to read-only too. |
| `readOnly` | `boolean` | `false` | Open the backing storage in read-only mode. |
| `active` | `boolean` | `true` | Whether loaded cores are automatically attached to active replication streams. |
| `unsafe` | `boolean` | `false` | Acknowledge that passing `primaryKey` directly is unsafe; required when `primaryKey` is set on a root store. |
| `treeCache` | `object` | — | Passed to the default `hypercore-storage` instance to size its tree-node cache, for example `{ maxSize: 8192 }`. Added in 7.11.1. |
| `manifestVersion` | `number` | `1` | The Hypercore manifest version used when the store creates new writable cores. Exposed as `store.manifestVersion`, and sessions inherit it. |
| `alwaysLatestBlock` | `boolean` | `false` | Open every loaded core with `allowLatestBlock` on, so its replicator asks for the latest block with each upgrade request. Sessions and namespaces inherit it, and an `allowLatestBlock` passed to `store.get()` takes precedence. Added in 7.13.0. |

## Errors

Coded errors this module can throw — catch them via `err.code`.

| Error | Thrown when |
| --- | --- |
| `ASSERTION` | if `primaryKey` is set on a root store without `unsafe: true`. |
