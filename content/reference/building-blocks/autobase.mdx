<Status level="stable" />

Autobase is a higher-level composition over underlying [Hypercores](/reference/building-blocks/hypercore). Writers append causal nodes to local cores, Autobase linearizes that graph into an eventually consistent order, and your `apply` handler materializes a deterministic view, often into a [Hyperbee](/reference/building-blocks/hyperbee).

## The apply handler

Treat `apply` like a **pure reducer**: given an ordered batch of nodes and a view handle, derive the next view state deterministically. Mutate only the `view` passed into `apply`. Do not:
* read or write external globals,
* open network connections, or
* assume ordering that Autobase has not yet committed.
**Side effects belong outside the linearization path.**

Autobase can reorder previously seen nodes when new causal information arrives. If `apply` is non-deterministic, different peers will diverge. Writer management (`host.addWriter`, indexer flags) and migration between `apply` versions are advanced topics—keep them inside `apply` only when they operate on the provided `view` and `host` handles.

## Install

```sh
npm i autobase
```

## Quickstart

This minimal flow opens a view, appends one record, updates the linearizer, and reads the materialized value back from `base.view`.

```js
import Corestore from 'corestore'
import Autobase from 'autobase'

const store = new Corestore('./autobase-demo')
const base = new Autobase(store, null, {
  valueEncoding: 'json',
  open: (viewStore) => viewStore.get({ name: 'messages', valueEncoding: 'json' }),
  apply: async (nodes, view) => {
    for (const { value } of nodes) await view.append(value)
  }
})

await base.ready()
await base.append({ type: 'message', text: 'hello from Autobase' })
await base.update()

console.log(await base.view.get(0))
// { type: 'message', text: 'hello from Autobase' }
```

Autobase can reorder previously seen nodes as new causal information arrives. Keep `open` and `apply` deterministic, derive state from the provided `store`, and mutate only the provided `view` inside `apply`.

## API Reference

### Constructor and lifecycle

#### `new Autobase(store, bootstrap, opts)`

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L77)

Instantiate an Autobase.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `store` | [`Corestore`](/reference/helpers/corestore) | — | The Corestore that holds the system, writer, and view cores. |
| `bootstrap` | [`Buffer\|string`](https://nodejs.org/api/buffer.html#class-buffer) | — | Key of an existing Autobase to load; omit or pass `null` to create a new one. |
| `opts` | `object` | `{}` | Configuration: `open`, `apply`, `close`, `valueEncoding`, `ackInterval`, `fastForward`, `encrypt`/`encryptionKey`, `optimistic`, and more (see the options table). |

| Option | Default | Description |
| --- | --- | --- |
| `open` | — | create the view |
| `apply` | — | handle nodes to update view |
| `optimistic` | `false` | Autobase supports optimistic appends |
| `close` | — | close the view |
| `valueEncoding` | — | encoding |
| `ackInterval` | `10000` | enable auto acking with the interval |
| `encryptionKey` | — | Key to encrypt the base |
| `encrypt` | `false` | Encrypt the base if unencrypted & no encryptionKey is set |
| `encrypted` | `false` | Expect the base to be encrypted, will throw an error otherwise, defaults to true if encryptionKey is set |
| `fastForward` | `true` | Enable fast forwarding. If passing \{ key: base.core.key \}, they autobase will fastforward to that key first. |
| `wakeup` | — | Set a custom wakeup protocol for hinting which writers are active, see `protomux-wakeup` for protocol details |
| `bigBatches` | `false` | Enable big batches. See `base.setBigBatches()` for details. |

```js
const base = new Autobase(store, bootstrap, {
  optimistic: true,
  async apply(nodes, view, host) {
    for (const node of nodes) {
      const { value } = node
      // Verify block
      if (value.password !== 'secrets') continue

      // Acknowledge only even numbers
      if (value.num % 2 === 0) await host.ackWriter(node.from.key)

      await view.append(value.num)
    }
  }
})

// Passing the password 'secrets' represents being verifiable
await base.append({ num: 3, password: 'secrets' }, { optimistic: true }) // will not be applied because `ackWriter` isnt called
await base.append({ num: 2, password: 'secrets' }, { optimistic: true }) // will be applied
await base.append({ num: 4, password: 'incorrect' }, { optimistic: true }) // will not be applied because the block isn't verifiable
```

When `optimistic` is enabled, validate optimistic blocks inside `apply` before calling `host.ackWriter(key)`. Otherwise any peer that can write to the underlying network path could attempt to inject values.

#### `await base.ready()`

Resolves once the base and its view are open and ready to use.

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L187)

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L110)

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L242)

#### `base.length`

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L258)

#### `base.signedLength`

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L250)

- Returns: `number`

#### `base.paused`

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L166)

### Writes and linearization

#### `await base.append(value, opts)`

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L1010)

Append a new entry to the autobase.

| Parameter | Type | Description |
| --- | --- | --- |
| `value` | [`*\|Array<*>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array) | The value, or array of values, to append. |
| `opts` | [`AppendOptions`](#appendoptions) | Append options. |

- Returns: [`Promise<number>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) — Resolves to the new core length once the value (or batch) has been appended.
- Throws:
  - if the autobase is closing.
  - if the local writer is not active/writable.

#### `await base.update()`

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L894)

Fetch all available data and update the linearizer.

- Returns: [`Promise<void>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) — Resolves once the linearizer has advanced.

```js
await base.update()
```

#### `await base.ack(bg = false)`

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L934)

Manually acknowledge the current state by appending a `null` node that references known head nodes. `null` nodes are ignored by the `apply` handler and only serve as a way to acknowledge the current linearized state. Only indexers can ack.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `bg` | `boolean` | `false` | If `bg` is set to `true`, the ack will not be appended immediately but will set the automatic ack timer to trigger as soon as possible. |

- Returns: [`Promise<void>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise) — Resolves once the ack has been handled.

```js
await base.ack()
```

Only indexers can acknowledge. An ack appends a `null` node that references the known heads so peers can converge faster without changing the view.

#### `base.heads()`

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L297)

Gets the current writer heads. A writer head is a node which has no causal dependents, aka it is the latest write. If there is more than one head, there is a causal fork which is pretty common.

- Returns: [`Array<object>`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array) — The head nodes (empty until the base is ready).

```js
const heads = base.heads()
```

#### `await base.pause()`

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L1983)

Pauses the autobase, preventing the next apply from running until `resume()` is called.

- Returns: `void`

```js
base.pause()
```

#### `await base.resume()`

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L1987)

Resumes a paused autobase and will check for an update.

- Returns: `void`

```js
base.resume()
```

#### `base.setBigBatches(enable = true)`

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/index.js#L326)

Set the autobase to enable or disable big batches. Big batches allow autobase to run the `apply` function on more blocks at once at the expense of being slower and less responsive.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `enable` | `boolean` | `true` | Whether to enable big batches. |

- Returns: `void`

```js
base.setBigBatches(true)
```

Big batches let Autobase call `apply` with more nodes at once, trading responsiveness for larger deterministic batches.

### View store helper

#### `store.get(name || { name, valueEncoding })`

Load a `Hypercore` by name (passed as `name`). `name` should be passed as a string.

- Throws: if no `name` is provided.

This `store` instance is the `AutoStore` passed into `open`, and it is the intended place to create the cores that make up your deterministic view.

### Apply host calls

#### `await host.addWriter(key, { indexer = true })`

Add a writer with the given `key` to the autobase allowing their local core to append. If `indexer` is `true`, it will be added as an indexer.

| Parameter | Default |
| --- | --- |
| `{ indexer` | `true }` |

- Throws: if called on the read-only public view.

#### `await host.removeWriter(key)`

Remove a writer from the autobase. This will throw if the writer cannot be removed.

- Throws: if called on the read-only public view, or if it would remove the last indexer.

This throws when the writer cannot be removed, such as when it would leave the system without a removable indexer set.

#### `await host.ackWriter(key)`

Acknowledge a writer even if they haven't been added before. This is most useful for applying `optimistic` blocks from writers that are not currently a writer.

- Throws: if called on the read-only public view.

#### `host.interrupt(reason)`

Interrupt the applying of writer blocks optionally giving a `reason`. This will emit an `interrupt` event passing the `reason` to the callback and halt all further applying. The base is not closed, but `base.interrupted` is set to the `reason` and later `base.append()` calls reject.

- Throws: if called on the read-only public view.

Interrupting halts applying and emits the `interrupt` event so the application can upgrade its `apply` logic or recover intentionally.

#### `host.removeable(key)`

[src](https://github.com/holepunchto/autobase/blob/v7.28.1/lib/apply-calls.js#L91)

Whether the writer with `key` can be removed without leaving the system
without a removable indexer set.

| Parameter | Type | Description |
| --- | --- | --- |
| `key` | [`Buffer`](https://nodejs.org/api/buffer.html#class-buffer) | The writer's key. |

- Returns: `boolean` — whether the writer for the given `key` can be removed.

```js
if (host.removeable(writerKey)) await host.removeWriter(writerKey)
```

The last indexer cannot be removed.
