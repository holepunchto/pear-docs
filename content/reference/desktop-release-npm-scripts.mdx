Pear Electron repositories wrap [`electron-forge`](https://www.electronforge.io/) (and on Linux, a small AppImage helper) behind `package.json` scripts so day-to-day work stays predictable. This page lists the script names used by [`hello-pear-electron`](https://github.com/holepunchto/hello-pear-electron#scripts) — the template every snippet in [Ship your app](/getting-started/ship) and [Deploy over-the-air updates](/getting-started/update) is built from. Your project may rename them; read `package.json` locally.

## `npm start`

Starts the app in development mode with OTA disabled, so a seeded `pear://` link does not replace your working tree while you hack:

```sh
# package.json
"start": "electron-forge start -- --no-updates"
```

To exercise the OTA path locally, drop the flag with an explicit `--updates`:

```sh
npm start -- --updates
```

## `npm run lint` / `npm run format`

Run [Prettier](https://prettier.io/) and the project's linter ([`lunte`](https://www.npmjs.com/package/lunte) in the template):

```sh
# package.json
"lint": "prettier --check . && lunte",
"format": "prettier --write . && lunte --fix"
```

Exact tools vary — inspect `scripts` in your repo.

## `npm run package`

Runs `electron-forge package` to produce a packaged app **without** the per-OS distributables (no `.app`/`.msix`/`.AppImage`). Useful for a quick smoke test:

```sh
# package.json
"package": "electron-forge package"
```

## `npm run make:linux`

Packages the app and then runs the [`scripts/build-app-image.sh`](https://github.com/holepunchto/hello-pear-electron/blob/main/scripts/build-app-image.sh) helper to produce an **AppImage** via [`app-builder-lib`](https://www.npmjs.com/package/app-builder-lib). Run on Linux or in CI with a Linux worker:

```sh
# package.json
"make:linux": "electron-forge package && ./scripts/build-app-image.sh"
```

Requires `jq` on the build host; the script reads `package.json` for the `productName`, version, description, and registered URL schemes that become the `.desktop` entry's `MimeType`.

## `npm run make:darwin`

Runs `electron-forge make --platform=darwin` on macOS to produce a `.app` and (with [`@electron-forge/maker-dmg`](https://www.npmjs.com/package/@electron-forge/maker-dmg)) a `.dmg`:

```sh
# package.json
"make:darwin": "electron-forge make --platform=darwin"
```

Without code-signing environment variables (`MAC_CODESIGN_IDENTITY`, `APPLE_TEAM_ID`, `APPLE_ID`, `APPLE_PASSWORD`), the `.app` runs locally but is quarantined on every other machine. See [Build desktop distributables](/how-to/operate-an-app/build-desktop-distributables) for the signing configuration.

## `npm run make:win32`

Runs `electron-forge make --platform=win32` on Windows to produce an `.msix`:

```sh
# package.json
"make:win32": "electron-forge make --platform=win32"
```

Requires the [Windows SDK](https://developer.microsoft.com/en-us/windows/downloads/windows-sdk/) and [PowerShell 7+](https://learn.microsoft.com/en-us/powershell/scripting/install/installing-powershell-on-windows) on the build host. Without `WINDOWS_CERTIFICATE_FILE`, [`@electron-forge/maker-msix`](https://www.npmjs.com/package/@electron-forge/maker-msix) generates a self-signed development certificate that is cached locally but not portable across machines.
