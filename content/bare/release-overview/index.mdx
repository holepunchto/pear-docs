## 2026-11-12 — Bare module updates

### bare-addon-resolve — v1.12.0

- Added: watchOS. A watchOS host also tries `watchos-universal` and `watchos-universal-simulator` prebuilds, and `resolve.linked` yields `.framework` names for it.
- Changed: hosts are split into their parts with `bare-host-parser`, so an architecture such as `arm64-32` is one condition. See [bare-addon-resolve](/bare/reference/bare/modules/bare-addon-resolve).

### bare-logger — v2.0.6

- Fixed (v2.0.5): lines no longer go missing or get cut short when stdout or stderr is a full non-blocking pipe. See [bare-logger](/bare/reference/bare/modules/bare-logger).

### bare-module — v7.5.2

- Changed (v7.5.1): hosts are split into their parts with `bare-host-parser`.
- Changed (v7.5.2): a WebAssembly addon throws `ADDON_HOST_INCOMPATIBLE` on FreeRTOS. See [bare-module](/bare/reference/bare/modules/bare-module).

### bare-module-traverse — v2.7.6

- Added (v2.7.5): watchOS hosts are parsed with `bare-host-parser`.
- Changed (v2.7.6): `resolve.bare` defaults `hosts` to `[host]`, without `wasi-wasm32`, on `freertos-` hosts. See [bare-module-traverse](/bare/reference/bare/modules/bare-module-traverse).

### bare-pack — v3.1.0

- Added: the `watchos` preset, which links addons and is not part of `mobile`. See [bare-pack](/bare/reference/bare/modules/bare-pack).

### bare-realm — v2.1.1

- Added (v2.1.0): `Realm.globalOf()` and `Realm.isFrom()`. The addon now requires Bare 1.37.0, up from 1.5.0.
- Fixed (v2.1.1): script names in stack traces no longer end in a NUL character. See [bare-realm](/bare/reference/bare/modules/bare-realm).

### bare-rpc — v2.0.0

- **Breaking:** cancelling a request sends a new message type, which a v1.x peer rejects by failing the session with `UNKNOWN_MESSAGE`. Destroying a reply stream before it ends, including breaking out of a `for await` loop over it, now cancels the request. Update both ends: the ports added cancellation in bare-rpc-swift 3.0.0, bare-rpc-kotlin 0.6.0, and bare-rpc-python 0.3.0.
- Added: `req.cancel(reason)`, and `signal` and `timeout` options on `rpc.request()`. With the `AbortController` option, handlers get `req.signal`. See [bare-rpc](/bare/reference/bare/modules/bare-rpc).

### bare-sidecar — v0.5.16

- Changed: runs Bare 1.37.1, up from 1.36.2. See [bare-sidecar](/bare/reference/bare/modules/bare-sidecar).

### bare-stow — v0.3.7

- Changed (v0.3.6): generated RPC code needs `bare-rpc` 2.x and `bare-abort-controller`, and bare-rpc-swift 3.x, bare-rpc-kotlin 0.6.x, or bare-rpc-python 0.3.x on the host.
- Changed: the `bare-kit` target pins bare-kit-swift `from: 2.3.0` and bare-kit-kotlin `v0.2.+`.
- Fixed (v0.3.3): `stow.link()` and `stow.resources` are declared in the types. See [bare-stow](/bare/reference/bare/modules/bare-stow).

### bare-system-logger — v1.0.7

- Added: FreeRTOS, where records go to stderr. See [bare-system-logger](/bare/reference/bare/modules/bare-system-logger).

### bare-tls — v3.2.1

- Changed: the bundled root certificates are curl's `cacert-2026-11-05.pem`, and the Android prebuilds link the C++ standard library statically. See [bare-tls](/bare/reference/bare/modules/bare-tls).

### bare-type — v1.6.0

- Added: `isDetachableArrayBuffer()` (v1.5.0), and `isMapIterator()` and `isSetIterator()` with their constants (v1.6.0).
- Changed (v1.5.0): `type.of()` returns `NON_DETACHABLE_ARRAYBUFFER` for an `ArrayBuffer` that can't be detached, such as the buffer of a `WebAssembly.Memory`. The addon now requires Bare 1.37.0. See [bare-type](/bare/reference/bare/modules/bare-type).

### bare-wasm-abi — v0.1.2

- Added: synchronous teardown callbacks, so the WebAssembly builds of `bare-svg` 1.1.1 and `bare-heif` 1.2.1 now load. A new threat model says the package is for trusted addons only. See [bare-wasm-abi](/bare/reference/bare/modules/bare-wasm-abi).

## 2026-11-11 — Bare v1.37.1

- Added: `watchos` in [`Bare.platform`](/bare/reference/bare/runtime#bareplatform) and `arm64-32`, the architecture of Apple Watch, in [`Bare.arch`](/bare/reference/bare/runtime#barearch), with the macros `BARE_PLATFORM_WATCHOS` and `BARE_ARCH_ARM64_32` in `bare/target.h`. Neither is in the [platform support](/bare/reference/bare/runtime#supported-platforms) table.
- Changed: addon resolution derives its conditions from the host with [`bare-host-parser`](https://github.com/holepunchto/bare-host-parser) instead of splitting it on hyphens, so a host whose architecture contains a hyphen, such as `watchos-arm64-32`, resolves. Existing hosts resolve as before.

## 2026-11-10 — Bare v1.37.0

- **Breaking (iOS):** an iOS app that embeds Bare must be signed with the `com.apple.developer.kernel.extended-virtual-addressing` entitlement. V8 reserves more virtual memory when it starts than iOS gives an app by default, so without the entitlement the app aborts on a device with `Failed to reserve virtual memory for process-wide V8 pointer compression cage`. See [Supported platforms](/bare/reference/bare/runtime#supported-platforms).
- Changed: V8 is version 15.7, up from 14.8, and includes DrumBrake, its WebAssembly interpreter. WebAssembly now runs on iOS, where V8 runs without a JIT and Bare had no `WebAssembly` global before, but interpreted, so more slowly than on other platforms. This makes [`bare-wasm`](/bare/reference/bare/modules/bare-wasm) and [WebAssembly addons](/bare/explanation/webassembly-addons) work on iOS. Android builds don't include DrumBrake and compile WebAssembly as before. See [`Bare.versions`](/bare/reference/bare/runtime#bareversions).
- Added: `freertos` in [`Bare.platform`](/bare/reference/bare/runtime#bareplatform) and `riscv32` and `armv8m` in [`Bare.arch`](/bare/reference/bare/runtime#barearch), with matching macros in `bare/target.h`. None of them is in the platform support table.
- Fixed: a suspend, wakeup, resume, or terminate that another thread requested just as the event loop ran out of work could be dropped. Once the process has begun to exit, these calls now do nothing and return `0`. See [Suspension](/bare/reference/bare/runtime#suspension).
- Changed: links `bare-sleep` as a builtin addon, which the bundled `bare-wasi` v0.1.3 uses to sleep. The lockfile also moves to [`bare-wasi`](/bare/reference/bare/modules/bare-wasi) v0.1.3, [`bare-wasm-abi`](/bare/reference/bare/modules/bare-wasm-abi) v0.1.2, [`bare-addon-resolve`](/bare/reference/bare/modules/bare-addon-resolve) v1.11.1, and [`bare-module-traverse`](/bare/reference/bare/modules/bare-module-traverse) v2.7.4.

## 2026-11-04 — Bare module updates

### bare-addon-resolve — v1.11.1

- Changed: each native host resolves on its own. A `prebuilds` directory further up is searched for the hosts that a closer one had nothing for, a host with no prebuild can still resolve to a linked addon, and the WebAssembly build is tried while any native host is unresolved. Before, the first step in which any host resolved ended the resolution for all of them. See [bare-addon-resolve](/bare/reference/bare/modules/bare-addon-resolve).

### bare-bluetooth — v0.6.5

- Fixed: on Linux, `central.disconnect()` accepts the `DiscoveredPeripheral` of a connection attempt that has not finished, as it does on Apple and Android. Before, it threw a `TypeError`. See [bare-bluetooth](/bare/reference/bare/modules/bare-bluetooth).

### bare-dns — v2.3.1

- Changed: `lookup()` and the resolver query methods throw an error with the new code `INVALID_HOSTNAME` for a hostname that contains a null byte. The bundled c-ares is 1.34.9, up from 1.34.4. See [bare-dns](/bare/reference/bare/modules/bare-dns).

### bare-fetch — v3.4.1

- Changed: redirects follow the Fetch Standard. A `301` or `302` response to a `POST`, and a `303` response to any method but `GET` or `HEAD`, turn the next request into a body-less `GET`. A redirect to another origin drops `Cookie`, `Host`, and `Proxy-Authorization` as well as `Authorization`. Before, every redirect resent the original method, body, and headers.
- Fixed: a `deflate` response body is decoded rather than compressed again, and a `Content-Encoding` that lists several codings, or `x-gzip`, is decoded. See [bare-fetch](/bare/reference/bare/modules/bare-fetch).

### bare-module-traverse — v2.7.4

- Changed (v2.7.4): an addon resolved for several native hosts must resolve for each of them. A host with no native build falls back to the `.wasm` build, is deferred when `deferUnresolved` is set, or fails the traversal with `ADDON_NOT_FOUND`.
- Changed (v2.7.3): the `bare-addon-resolve` dependency is `^1.11.0`, up from `^1.5.0`, so `.wasm` builds are always found. v2.7.4 raises it to `^1.11.1`. See [bare-module-traverse](/bare/reference/bare/modules/bare-module-traverse).

### bare-os — v3.9.4

- Changed: process IDs, signals, and priorities are checked to be 32-bit signed integers, user and group IDs 32-bit unsigned integers, and a priority to be from `-20` to `19`, with a `RangeError` otherwise. Strings that `chdir()`, `setProcessTitle()`, and the environment functions pass on throw a `TypeError` when they contain a null byte. See [bare-os](/bare/reference/bare/modules/bare-os).

### bare-pipe — v4.4.0

- Added: `pipe.remoteCredentials()` returns the process, user, group, and Windows SID of the other end, as the operating system reports them, and the `ownerOnly` option of `server.listen()` restricts a pipe to the current user. See [Local access control](/bare/reference/bare/modules/bare-pipe#local-access-control).

### bare-rpc — v1.5.0

- Added (v1.4.0): an `opts` argument to `new RPC()` with `maxFrameSize`, and checks that fail the session with `FRAME_TOO_LARGE` or `INVALID_MESSAGE` when the peer sends a bad frame. The typings declare `RPC.CommandRouter`.
- Added (v1.5.0): the `maxBufferedBytes` option and the `STREAM_OVERFLOW` and `UNEXPECTED_STREAM` errors. See [bare-rpc](/bare/reference/bare/modules/bare-rpc).

### bare-sidecar — v0.5.15

- Added: `sidecar.kill()` (v0.5.10), a `file:` URL as the entry (v0.5.9), and `Sidecar.versions`, also exported as `bare-sidecar/versions` (v0.5.15).
- Changed (v0.5.10): `sidecar.destroy()` closes the stream only once the process has exited.
- Fixed (v0.5.11, v0.5.12): an `EPIPE` or `ECONNRESET` from the IPC channel of an exiting process no longer destroys the sidecar with an error.
- Changed: bundles Bare v1.36.2, up from v1.34.1. See [bare-sidecar](/bare/reference/bare/modules/bare-sidecar).

### bare-stow — v0.3.2

- **Breaking:** `out` is the directory of a harness package, with a manifest that declares the dependencies of the harness, and the harness is booted with its `start()`. The `bare-stow/protocol` and `bare-stow/host` subpaths are gone; the protocol and the host side are separate packages.
- Added: harnesses for Kotlin, Python, and Swift hosts as well as JavaScript, the `bare-kit` target, `stow.link()`, and the `bare-stow pack` and `bare-stow link` commands.
- Changed (v0.3.2): the entry shims that `stow()` generates for the bundle are CommonJS, so they also load in a graph whose ES modules are converted to CommonJS. See [bare-stow](/bare/reference/bare/modules/bare-stow).

### bare-tls — v3.2.0

- Changed: the `onconnect` callback of `createConnection()` runs once the TLS handshake has completed, not when the TCP connection opens.
- Added: the socket that `createConnection()` returns, typed `TLSNetSocket`, has `setKeepAlive()`, `setNoDelay()`, and `setTimeout()`, and emits `timeout`.
- Changed: a client socket throws a `TypeError` for a `host` that ends in a numeric label but is not a canonical IPv4 address, such as `127.1`. See [bare-tls](/bare/reference/bare/modules/bare-tls).

### bare-tty — v5.2.2

- Changed: `setRawMode(true)` sets the new `constants.mode.RAW_VT`, which on Windows delivers keys such as Shift+Tab as escape sequences. See [bare-tty](/bare/reference/bare/modules/bare-tty).

### bare-url — v2.5.6

- Fixed: a query string with a malformed percent escape no longer throws a `URIError`. See [bare-url](/bare/reference/bare/modules/bare-url).

## 2026-11-03 — Bare Kit 3

### bare-kit — v3.0.0 and v3.0.1

- **Breaking:** Bare Kit is now a standalone C library, declared in `include/bare-kit.h`. The Objective-C and Java bindings are no longer in the repository. Their replacements are [`bare-kit-swift`](https://github.com/holepunchto/bare-kit-swift) for iOS and macOS and [`bare-kit-kotlin`](https://github.com/holepunchto/bare-kit-kotlin) for Android and the JVM. See [Native bindings](/bare/reference/bare/bare-kit#native-bindings).
- **Breaking:** the C API is new. `bare_worklet_create()`, `bare_ipc_create()`, and `bare_ipc_poll_create()` replace the `_alloc()` and `_init()` pairs, `bare_ipc_read()` copies into a buffer of the caller, and the lifecycle callbacks take the value and `data`. Push (`bare_worklet_push()` and the `push` event of the `BareKit` global), the `BareKit` global itself, and the `assets` option are gone. Use `Bare.IPC` inside the worklet. See [C API](/bare/reference/bare/bare-kit#c-api).
- Changed: the IPC is an in-process queue rather than a pipe. Ending a side is a half-close, and an open IPC keeps the worklet running until both sides have ended it. See [IPC](/bare/reference/bare/bare-kit#ipc).
- Added: `bare_worklet_on_exit()`, called once with the exit code after the worklet has torn down, `bare_worklet_teardown()`, `bare_ipc_end()`, and `bare_ipc_close()`. A relative filename names a resource of the app, and on Android the assets that `<name>.assets` lists are extracted from the APK before the bundle first runs. See [Loading a bundle](/bare/reference/bare/bare-kit#loading-a-bundle).
- Added: on Android, the worklet publishes `bare.android.context.v1` to addons when the host passes an application context. See [`bare.android.context.v1`](/bare/reference/bare/embedder-context#bareandroidcontextv1).
- Added in v3.0.1: a `bare::kit::exports` CMake target that limits the exports of a shared library that links Bare Kit statically to the functions of Bare Kit and the symbols of Bare that addons need. See [Addons](/bare/reference/bare/bare-kit#addons).
- Changed: embeds Bare 1.36.1 in v3.0.0 and Bare 1.36.2 in v3.0.1, up from 1.33.4. See [Bundled Bare version](/bare/reference/bare/bare-kit#bundled-bare-version).

### react-native-bare-kit — v0.17.0 and v0.17.1

- **Breaking:** v0.17.0 moves onto Bare Kit 3 and no longer includes Bare Kit. The app brings it, with the addons and assets of its worklets, through `bare-stow link --target bare-kit`, and `new Worklet()` throws if it is missing. The `ios/addons` and `android/src/main/addons` directories of the package are no longer built into the app. See [Linking addons and assets](/bare/reference/bare/bare-kit#linking-addons-and-assets).
- **Breaking:** v0.17.0 removes the `assets` option and the `BareKit` global inside the worklet. Use `Bare.IPC`. See [Worklet](/bare/reference/bare/bare-kit#worklet).
- Added in v0.17.0: `worklet.IPC.end()` half-closes the host side of the IPC. A relative `filename` passed to `start()` names a resource of the app. See [IPC](/bare/reference/bare/bare-kit#ipc).
- Fixed in v0.17.0: the static `Worklet.wakeup()` no longer throws a `TypeError`.
- Added in v0.17.1: the `exit` event and `worklet.wait()`, which report the exit code of the worklet. When the worklet exits on its own, its IPC emits what the worklet wrote and then ends. The `started`, `terminated`, and `suspended` getters are now in the type declarations. See [Events](/bare/reference/bare/bare-kit#events).

## 2026-10-21 — Bare v1.36.0

- Added: WebAssembly addons. An addon package can ship a WebAssembly build, `prebuilds/wasi-wasm32/<name>.wasm`, and Bare loads it sandboxed through WASI: through WASI, the addon reaches only the directories, streams, and randomness that a WASI provider grants, though it can still reach whatever JavaScript in its realm can. Ask for it with the `host` import attribute, and name the provider with the `wasi` attribute, as in `require('bare-sqlite', { with: { host: 'wasi-wasm32', wasi: './wasi.js' } })` or the same `with` clause on `import`. Without the attribute, Bare uses the `.wasm` build only when the package has no native build or linked addon for the platform, and with no provider it grants nothing except clocks. The support comes from the bundled [`bare-module`](/bare/reference/bare/modules/bare-module#webassembly-addons) v7.5.0, not from Bare's own source. See [WebAssembly addons](/bare/reference/bare/modules/bare-module#webassembly-addons).
- Changed: on a process sealed with `Bare.Addon.seal()`, an addon resolved after the seal whose native build the process has not loaded falls back to the package's `.wasm` build, if it ships one, instead of failing with `CANNOT_LOAD`. A package without a `.wasm` build now fails there with `ADDON_NOT_FOUND` instead of `CANNOT_LOAD`. An addon resolved before the seal, such as one reached through a static `require()` from the sealing module or any module linked with it, still fails with `CANNOT_LOAD`. Inside a bundle, which keeps the resolutions recorded at pack time, nothing falls back. See [`Bare.Addon`](/bare/reference/bare/runtime#bareaddon).
- Changed: `Bare.suspend()`, `Bare.wakeup()`, and the `suspend()` and `wakeup()` methods of a thread throw a `RangeError` for a `linger` or `deadline` above `2147483647`. Before, such a value wrapped to a 32-bit signed integer, so `Infinity` became `0` and a deadline that became negative left the wakeup timer never firing. See [`Bare.suspend()`](/bare/reference/bare/runtime#baresuspendlinger).
- Deprecated: every form of `new Bare.Thread()` except `new Thread(filename, source[, options])`, including the callback forms that run the body of a function on the thread. `Thread.create()` has been deprecated since 1.31.0. Pass the source, or use [`bare-thread`](https://github.com/holepunchto/bare-thread). The deprecated forms still work. See [`Bare.Thread`](/bare/reference/bare/runtime#barethread).
- Fixed: a resume or wakeup could be missed after an explicit `Bare.idle()`.
- Changed: bundles [`bare-module`](/bare/reference/bare/modules/bare-module) v7.5.0, up from v7.4.0, and [`bare-module-traverse`](/bare/reference/bare/modules/bare-module-traverse) v2.7.2, up from v2.6.0, and adds [`bare-wasm-abi`](/bare/reference/bare/modules/bare-wasm-abi) v0.1.1, [`bare-wasi`](/bare/reference/bare/modules/bare-wasi) v0.1.2, and [`bare-wasm`](/bare/reference/bare/modules/bare-wasm) v0.1.0, and bundles `bare-pipe` v4.4.0, up from v4.3.1. The bundled `bare-wasi` serves the loader and can't be imported, so an app installs its own `bare-wasi` and `bare-directory` for a WASI provider. See [Bare module updates](#2026-10-21--bare-module-updates).
- Changed: the typings declare `Bare.IPC` in the `Bare` namespace. Nothing changes at run time.

## 2026-10-21 — Bare module updates

### bare-directory — v0.1.0

- Added: a new module for capability-based directory access. A handle opened from a path reaches only what is inside the directory, operations take a single name rather than a path, symbolic links are never followed, and rights can only be narrowed. The kernel enforces the confinement as far as each platform allows. [`bare-wasi`](/bare/reference/bare/modules/bare-wasi) uses it to give a WebAssembly addon host directories. See [bare-directory](/bare/reference/bare/modules/bare-directory).

### bare-module — v7.5.0

- Added: WebAssembly addons. The `host` import attribute resolves the addons of a module and its dependencies for `wasi-wasm32`, and the `wasi` attribute names the module that provides their WASI capabilities. The loader runs a `.wasm` addon through [`bare-wasm-abi`](/bare/reference/bare/modules/bare-wasm-abi). See [WebAssembly addons](/bare/reference/bare/modules/bare-module#webassembly-addons).
- Added: the `wasi` loader option, a function that returns the WASI options of an addon imported without a `wasi` attribute. A cache read from a loader with another `wasi` throws `CACHE_INCOMPATIBLE`.
- Added: the errors `ADDON_HOST_INCOMPATIBLE` and `ADDON_WASI_INCOMPATIBLE`. The addons of a package load in one context per loader, and importing the package under another host or provider throws.
- Changed: the minimum Bare is 1.35.0, up from 1.32.0. On a sealed process, the loader skips native addons that `Bare.Addon.loaded()`, added in Bare 1.35.0, reports as not loaded.

### bare-module-traverse — v2.7.2

- Added (v2.7.0): `conditions` in the options of `traverse.resolve.bare` and `traverse.resolve.node` mix in additional resolver conditions, and a `host` attribute adds the `wasi` and `wasm32` conditions to those of the native host. The options type now extends the options of both `bare-module-resolve` and `bare-addon-resolve`. See [bare-module-traverse](/bare/reference/bare/modules/bare-module-traverse).
- Added (v2.7.1): the `mount` option, the URL that an entry bundle is mounted at, and the addons and assets that an imported bundle declares are added to the traversal's `artifacts`.
- Added: the `Dependency` type declares `wasi`, the URL of the WASI provider of a WebAssembly addon, which the traversal has set since v2.6.0.
- Changed (v2.7.0): queued subgraphs are walked first in, first out, so dependencies are yielded in a different order.

### bare-pack — v3.0.2

Patch releases in this window (dependency bumps, prebuild updates) and most of Bare's ecosystem modules (bare-buffer, bare-http1, bare-inspect, etc.) aren't covered yet—that backfill is in progress as a separate effort across Bare, P2P, and Pear. See each module's GitHub releases for the raw upstream record in the meantime.
</Callout>
