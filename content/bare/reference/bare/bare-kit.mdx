[`bare-kit`](https://github.com/holepunchto/bare-kit) embeds [Bare](/bare/reference/bare/runtime) in native application development. It provides a web-worker-like API for starting and managing isolated Bare threads—called **worklets**—each exposing an IPC channel with bindings for several languages. [`react-native-bare-kit`](https://github.com/holepunchto/react-native-bare-kit) wraps the same API for React Native and Expo. For the architecture this enables, see [One core, many platforms](/bare/explanation/bare-on-native).

<Callout type="info">
A *worklet* is an isolated Bare thread managed by the host app. The name avoids confusion with the worker threads of [`bare-worker`](/bare/reference/bare/modules).
</Callout>

## Worklet

A worklet runs a Bare entry script on a background thread. Create one, start it with an entry filename and source, and manage its [lifecycle](/bare/reference/bare/runtime#lifecycle).

### Constructor

- `new Worklet([options])`— create a worklet.
- `new Worklet(id[, options])` <Since v="0.10.5" />— create a worklet under a string `id`. When a worklet with an `id` starts, any earlier worklet holding the same `id` is terminated, so at most one live worklet owns an `id`. `id` must be a string.

<VersionGate since="0.9.2">
`options` is an object with `memoryLimit` (a number, the memory limit of the worklet's JavaScript heap, where `0` takes the default) and `assets` (a string, the directory that assets bundled with the worklet are unpacked into, which the worklet needs both read and write access to; see [Loading a bundle](#loading-a-bundle)). Both are optional, and without `assets` a bundle that references an asset fails at runtime. <Since v="0.9.2" />
</VersionGate>

### Actions

- `start(filename[, args])`, `start(filename, source[, args])`— start the worklet running `source` as `filename`. `source` is a string or a `Uint8Array`. Without `source`, the worklet reads `filename` itself. `args` is an array of strings that becomes `Bare.argv` inside the worklet as it is, so unlike on a desktop it holds no executable path and no entry path. A worklet can be started once, and starting it again, or starting one that has been terminated, throws.
- `suspend([linger])`— suspend execution, keeping the process alive for up to `linger` milliseconds before it fully exits. A negative or omitted `linger` takes the platform default of 30 seconds. On iOS the default, and the limit for any `linger`, is the background time the OS grants the app, which is 30 seconds when the OS reports no limit.
- `resume()`— resume a suspended worklet.
- `wakeup([deadline])`— wake the worklet during suspension. Work may run until `deadline`, after which it suspends again. `deadline` defaults to `0` and follows the same rules as `linger`: a negative value takes the platform default, and on iOS a longer value is shortened to the background time the OS grants.
- `update([state])`— apply a host app-lifecycle state (React Native's `AppStateStatus`) to the worklet: `'active'` resumes it, `'background'` suspends it, and any other state does nothing. `state` defaults to `AppState.currentState`. React Native already forwards app-state changes to every started worklet, and `start()` applies the current state once the worklet is running, so a worklet started while the app is in the background is suspended straight away. You rarely need to call this yourself.
- `terminate()`— terminate the worklet and destroy its IPC. Calling it on a terminated worklet does nothing.

`suspend()`, `resume()`, and `wakeup()` throw if the worklet has not been started or has been terminated, as does `update()` when it ends up resuming or suspending.

<Callout type="warn">
In react-native-bare-kit 0.15.6 and 0.16.0, `start(filename)` with no second argument throws a `TypeError`, although the type declarations allow it, because an omitted `source` is `undefined`, which the argument check rejects. To start from `filename` alone, pass an empty `args` array: `worklet.start('/app.js', [])`.
</Callout>

<Callout type="info">
`suspend`, `resume`, `wakeup`, and `update` are also available as **static** methods (`Worklet.suspend()`, etc.), driving every started worklet the host manages at once rather than one instance.
</Callout>

<Callout type="warn">
In react-native-bare-kit 0.15.6 and 0.16.0, the static `Worklet.wakeup()` calls `worklet.deadline(...)`, which doesn't exist, so it throws a `TypeError` when any started worklet has not been terminated. Call `wakeup()` on each worklet instead.
</Callout>

### Properties

- `worklet.IPC`— the [IPC](#ipc) channel to the worklet, a [`streamx`](https://github.com/mafintosh/streamx) `Duplex` stream with a `worklet` property pointing back at it.
- `worklet.started`, `worklet.terminated`, `worklet.suspended`— booleans for the lifecycle state. These are in the JavaScript but not in the type declarations.

### Events

`Worklet` is an event emitter, and each event mirrors the same event on `Bare` inside the worklet, as described under [Lifecycle methods](/bare/reference/bare/runtime#lifecycle-methods).

- `suspend`— `(linger)`, the worklet is suspending.
- `wakeup`— `(deadline)`, the worklet woke up during suspension.
- `idle`— `()`, the worklet has gone idle. <Since v="0.14.0" />
- `resume`— `()`, the worklet resumed.
- <Until v="0.14.0" label="Removed in 0.14.0" /> `start` and `terminate`— earlier versions emitted these as well. Check `worklet.started` and `worklet.terminated` instead.

### React Native

```js
import { Worklet } from 'react-native-bare-kit'
import b4a from 'b4a'

const worklet = new Worklet()

const source = `
const { IPC } = BareKit

IPC.on('data', (data) => console.log(data.toString()))
IPC.write(Buffer.from('Hello from Bare!'))
`

worklet.start('/app.js', source)

const { IPC } = worklet
IPC.on('data', (data) => console.log(b4a.toString(data)))
IPC.write(b4a.from('Hello from React Native!'))
```

### iOS

```objc
#import <BareKit/BareKit.h>

BareWorkletConfiguration *options = [BareWorkletConfiguration defaultWorkletConfiguration];
options.memoryLimit = 1024 * 1024 * 24; // 24 MiB

BareWorklet *worklet = [[BareWorklet alloc] initWithConfiguration:options];

NSString *source = @"console.log('hello from the worklet')";
[worklet start:@"/app.js" source:[source dataUsingEncoding:NSUTF8StringEncoding] arguments:@[]];
```

### Android

```java
import to.holepunch.bare.kit.Worklet;
import java.nio.charset.StandardCharsets;

Worklet.Options options = new Worklet.Options()
  .memoryLimit(24 * 1024 * 1024); // 24 MiB

Worklet worklet = new Worklet(options);

String source = "console.log('hello from the worklet')";
worklet.start("/app.js", source, StandardCharsets.UTF_8, null);
```

## Native bindings

The iOS and Android bindings expose the same worklet through their own classes. Neither has `wakeup()`, `update()`, or events.

### iOS

Declared in [`apple/BareKit/BareKit.h`](https://github.com/holepunchto/bare-kit/blob/main/apple/BareKit/BareKit.h).

**`BareWorkletConfiguration`**

- `memoryLimit` (`NSUInteger`)— the memory limit of the worklet's JavaScript heap, where `0` takes the default.
- `assets` (`NSString`, nullable)— the directory that bundled assets are unpacked into.
- `+defaultWorkletConfiguration`— a configuration with the defaults.

**`BareWorklet`**

- `-initWithConfiguration:`— create a worklet. The configuration may be `nil`.
- `+optimizeForMemory:`— a class method that reduces memory use, including by limiting the libuv thread pool to one thread instead of four. The platform is set up when the first worklet starts, so call it before you start one.
- `-start:arguments:`, `-start:source:arguments:` (`NSData`), `-start:source:encoding:arguments:` (`NSString`)— start from `filename`, or from `source`. Without `source` the worklet reads `filename` itself.
- `-start:ofType:arguments:`, `-start:ofType:inBundle:arguments:`, `-start:ofType:inDirectory:arguments:`, `-start:ofType:inDirectory:inBundle:arguments:`— look a file up in an app bundle (`NSBundle.mainBundle` unless `inBundle:` is given, inside the `inDirectory:` subdirectory if given) with `pathForResource:ofType:`, then start from that path.
- `-suspend`, `-suspendWithLinger:`, `-resume`, `-terminate`— the lifecycle methods. `-suspend` uses a linger of `-1`, the platform default.
- `-push:completion:` and `-push:queue:completion:`, with `NSData` or `NSString` payloads (the `NSString` forms take an `encoding:`)— see [Push](#push).

### Android

Declared in [`Worklet.java`](https://github.com/holepunchto/bare-kit/blob/main/android/src/main/java/to/holepunch/bare/kit/Worklet.java) and [`IPC.java`](https://github.com/holepunchto/bare-kit/blob/main/android/src/main/java/to/holepunch/bare/kit/IPC.java), in the package `to.holepunch.bare.kit`.

**`Worklet.Options`**

- `memoryLimit(int)`— the memory limit of the worklet's JavaScript heap in bytes, where `0` takes the default.
- `assets(String)`— the directory that bundled assets are unpacked into.

**`Worklet`** implements `Closeable`, and `close()` terminates it.

- `new Worklet(options)`— create a worklet. `options` may be `null`.
- `start(String filename, String[] arguments)`— start from `filename`, which the worklet reads itself.
- `start(String filename, ByteBuffer source, String[] arguments)`, `start(String filename, String source, Charset charset, String[] arguments)`, `start(String filename, String source, String charset, String[] arguments)`— start from `source`. `arguments` may be `null`.
- `start(String filename, InputStream source, String[] arguments)`— start from the contents of a stream. It calls `source.reset()` before it reads the stream, and it is declared to throw `IOException`.
- `suspend()`, `suspend(int linger)`, `resume()`, `terminate()`— the lifecycle methods. A negative linger, which `suspend()` uses, is 30 seconds.
- `push(...)`— see [Push](#push).

## Push

Push sends a single request from the host to the worklet and delivers the worklet's reply, for one-off calls where an [IPC](#ipc) stream is more than needed. It is available on iOS and Android, but not in react-native-bare-kit.

In the worklet, handle the `push` event on the `BareKit` global. The listener is passed the payload as a `Buffer` and a `reply(err, payload[, encoding])` function. Call `reply` once, with an error to fail the request or a payload to answer it, because later calls do nothing. A string payload is encoded with `encoding`, and the host receives `String(err)` as the error message. If the worklet has no `push` listener, the request completes with no reply and no error.

```js
BareKit.on('push', (payload, reply) => {
  reply(null, 'pong: ' + payload.toString())
})
```

On the host, pass a payload and receive the reply on a completion handler.

- **iOS:** `-push:completion:` and `-push:queue:completion:` take an `NSData` payload and deliver an `NSData` reply. The `NSString` forms take an `encoding:`, which they use to encode the payload and to decode the reply, and deliver an `NSString`. The reply is `nil` when the worklet sends none. When the worklet replies with an error, `error` is an `NSError` in the domain `to.holepunch.bare.kit` with the code `-1`, and its localized description is the message from the worklet. The completion runs on `queue`, which is the main queue when you leave it out.
- **Android:** `push(ByteBuffer payload, PushCallback<ByteBuffer> callback)` and `push(String payload, Charset charset, PushCallback<String> callback)` call back with `apply(reply, exception)` on the `Looper` of the calling thread, and `push(ByteBuffer payload, Looper looper, PushCallback<ByteBuffer> callback)` calls back on the `Looper` you pass. The `reply` is `null` when the worklet sends none, and `exception` is an `Error` that carries the worklet's message when the worklet replies with an error. The `String` forms that take a `Looper` ignore it and call back on the `Looper` of the calling thread. Each `String` form also accepts a charset name in place of the `Charset`. `push(ByteBuffer payload, long timeout, TimeUnit unit)` and `push(String payload, Charset charset, long timeout, TimeUnit unit)` instead block until the reply or the timeout, return `null` if there is no reply or the timeout passes, and throw that `Error` when the worklet replies with an error. They declare `InterruptedException`.

## IPC
<VersionSection since="0.9.1" />

Bare Kit provides an IPC channel between the host app and a worklet. Inside the worklet it is `BareKit.IPC`, the same object as [`Bare.IPC`](/bare/reference/bare/runtime#bareipc). On the host it depends on the binding.

**React Native.** `worklet.IPC` is a [`streamx`](https://github.com/mafintosh/streamx) `Duplex` stream, so use it as one: listen for `data`, call `write()`, and `destroy()` it. Writes queue behind a slow worklet instead of being partial. It opens when the worklet starts, so you can write before calling `start()` and the writes wait until the worklet is running. It is destroyed along with the worklet.

**iOS and Android.** `BareIPC` (`-initWithWorklet:`) and `IPC` (`new IPC(worklet)`) offer a polling API and an async API, in both a synchronous and an asynchronous style. Create one after you start the worklet, because the channel comes from the running worklet.

<Callout type="warn">
On iOS and Android, IPC operations are **non-blocking** regardless of which API you use. They may return partial results—for example writing fewer bytes than requested—and require polling to complete. On iOS the `readable` and `writable` callbacks, and the completions of async reads and writes that have to wait for the channel, run on a dedicated serial queue, so synchronize any state they share. On Android the same callbacks and completions run through the `Looper` of the thread that created the `IPC`.
</Callout>

**Polling API** (callback-driven, use when you want event-triggered reads/writes):

- `readable`— callback invoked when data is available to read. On iOS it is a property, and on Android it is set with `readable(callback)`.
- `writable`— callback invoked when data can be written. On iOS it is a property, and on Android it is set with `writable(callback)`.
- `read()`— synchronously read available data. It returns `nil` (`null` on Android) when none is available yet, so wait for `readable` before retrying. At end-of-stream, once the worklet has closed its end, it returns empty data. A worklet closes its end of the channel when it exits.
- `write(data)`— synchronously write data; returns the number of bytes written, which is `0` when the channel cannot take more yet.

**Async API** (completion-based, use when you want a single async operation):

- `read(callback)`— asynchronously read data with a completion callback, which receives the data and an error. At end-of-stream the data is `nil` (`null` on Android).
- `write(data, callback)`— asynchronously write data with a completion callback, which receives an error if the write failed.

In bare-kit 2.5.5 the `error` that these callbacks receive is always `nil` (`null` on Android).

**Utility:**

- `close()`— close the IPC connection.

Inside the worklet the channel is `BareKit.IPC`, the same object as [`Bare.IPC`](/bare/reference/bare/runtime#bareipc). On the host it is a `BareIPC` (iOS), an `IPC` (Android), or the `IPC` object on the React Native `Worklet`.

For typed, schema-generated messaging over this channel instead of raw bytes, layer [`bare-rpc`](/bare/reference/bare/modules) on top—see [Type a native RPC bridge](/bare/how-to/run-on-native/type-a-native-rpc-bridge).

## C API

The iOS and Android bindings, and the Linux and Windows builds of `libbare-kit`, sit on a C API declared in [`shared/worklet.h`](https://github.com/holepunchto/bare-kit/blob/main/shared/worklet.h) and [`shared/ipc.h`](https://github.com/holepunchto/bare-kit/blob/main/shared/ipc.h). Use it to host worklets from your own C or C++ code. Functions return `0` on success and a negative value on failure, except where noted.

### Worklet

```c
typedef struct bare_worklet_options_s {
  size_t memory_limit;
  const char *assets;
} bare_worklet_options_t;
```

`memory_limit` is the memory limit of each JavaScript heap in bytes, applied to each thread individually. By default it is inferred from the physical memory of the device. `assets` is the directory that bundled assets are unpacked into, which the worklet needs read and write access to. By default assets cannot be referenced, and doing so is a runtime error.

- `bare_worklet_optimize_for_memory(bool enabled)`— trade performance for memory. It must be configured before the first worklet starts.
- `bare_worklet_alloc(bare_worklet_t **result)`, `bare_worklet_init(bare_worklet_t *worklet, const bare_worklet_options_t *options)`, `bare_worklet_destroy(bare_worklet_t *worklet)`— allocate, initialize and release a worklet. `options` may be `NULL`, and its `assets` string is copied. `bare_worklet_destroy()` releases what the worklet holds, including its IPC descriptors, but does not free the struct that `bare_worklet_alloc()` returned.
- `bare_worklet_start(bare_worklet_t *worklet, const char *filename, const uv_buf_t *source, int argc, const char *argv[])`— start the worklet on a new thread. `source` may be `NULL`, in which case the worklet reads `filename` itself. The new thread has read `filename`, `source`, and `argv` by the time the call returns, so none of them has to stay valid after it. The call does not wait for the worklet to run the entry script.
- `bare_worklet_suspend(worklet, int linger)`, `bare_worklet_resume(worklet)`, `bare_worklet_wakeup(worklet, int deadline)`, `bare_worklet_terminate(worklet)`— the lifecycle, equivalent to [`bare_suspend()`, `bare_resume()`, `bare_wakeup()` and `bare_terminate()`](/bare/reference/bare/runtime#suspension) on the worklet's process. A negative `linger` or `deadline` takes the platform default of 30 seconds. On iOS the default, and the limit for any `linger` or `deadline`, is the background time the OS grants the app.
- `bare_worklet_on_suspend()`, `bare_worklet_on_wakeup()`, `bare_worklet_on_idle()`, `bare_worklet_on_resume()`— `(worklet, cb, data)`, set the listener for the matching event. The listener types are [`bare_suspend_cb`, `bare_wakeup_cb`, `bare_idle_cb` and `bare_resume_cb`](/bare/reference/bare/runtime#listeners).
- `bare_worklet_get_data(worklet)`, `bare_worklet_set_data(worklet, void *data)`— a pointer of your own to keep on the worklet.
- `bare_worklet_push(worklet, bare_worklet_push_t *req, const uv_buf_t *payload, bare_worklet_push_cb cb)`— [push](#push) `payload` to the worklet. `req` is yours to allocate, and it and `payload` must stay valid until `cb` runs. `cb` is `void (*)(bare_worklet_push_t *req, const char *error, const uv_buf_t *reply)`, where `error` is `NULL` on success and `reply` is `NULL` when there is no reply. `cb` runs on the worklet's thread, and `error` and `reply` are valid only until it returns. `bare_worklet_push_get_data()` and `bare_worklet_push_set_data()` keep a pointer of your own on `req`. In bare-kit 2.5.5 the Windows build does not export `bare_worklet_push()`, `bare_worklet_push_get_data()`, or `bare_worklet_push_set_data()`, because `win32/worklet.def` does not list them.

### IPC

- `bare_ipc_alloc(bare_ipc_t **result)`, `bare_ipc_init(bare_ipc_t *ipc, bare_worklet_t *worklet)`, `bare_ipc_destroy(bare_ipc_t *ipc)`— open an IPC channel to a started worklet, and close it. `bare_ipc_get_incoming()` and `bare_ipc_get_outgoing()` return its descriptors.
- `bare_ipc_read(bare_ipc_t *ipc, void **data, size_t *len)`— read up to `BARE_IPC_READ_BUFFER_SIZE` (64 KiB) without blocking. On success it stores a pointer to the data in `*data` and its length in `*len`, which is `0` once the worklet has closed its end. The buffer belongs to `ipc` and is overwritten by the next read.
- `bare_ipc_write(bare_ipc_t *ipc, const void *data, size_t len)`— write without blocking, and return the number of bytes written, which may be fewer than `len`.
- `bare_ipc_read()` and `bare_ipc_write()` return `bare_ipc_would_block` (`-1`) when they cannot proceed yet, and `bare_ipc_error` (`-2`) on an error.
- `bare_ipc_poll_alloc()`, `bare_ipc_poll_init(bare_ipc_poll_t *poll, bare_ipc_t *ipc)`, `bare_ipc_poll_destroy()`, `bare_ipc_poll_start(poll, int events, bare_ipc_poll_cb cb)`, `bare_ipc_poll_stop()`— call `cb(poll, events)` when the channel becomes readable or writable. `events` is `bare_ipc_readable`, `bare_ipc_writable` or both ORed. `bare_ipc_poll_get_ipc()`, `bare_ipc_poll_get_data()` and `bare_ipc_poll_set_data()` return the channel and keep a pointer of your own.
- Where `cb` runs depends on the platform: a dedicated serial dispatch queue on Apple platforms, the `ALooper` of the thread that called `bare_ipc_poll_init()` on Android, and a thread that the library owns on Linux and Windows.
- On Windows, `bare_ipc_write()` copies `data` and accepts all of it, or returns `bare_ipc_would_block` while an earlier write is still pending. `bare_ipc_read()` never returns a length of `0` there: after the worklet closes its end it keeps returning `bare_ipc_would_block`, because `win32/ipc.c` does not report the end of the stream yet.

## Loading a bundle

Instead of inline source, a worklet can start from a bundle produced by [`bare-pack`](/bare/reference/bare/modules). The entry filename's extension must be `.bundle`:

```js
import { Worklet } from 'react-native-bare-kit'
import bundle from './my.bundle.js' // output by bare-pack

const worklet = new Worklet()
worklet.start('/app.bundle', bundle)
```

See [Bundle a Bare app](/bare/how-to/run-on-native/bundle-a-bare-app) for producing the bundle.

If the bundle carries assets and the worklet was created with an `assets` directory, the worklet unpacks the assets into a subdirectory of it, named after a hash of the bundle's id. It does so once, and reuses the directory on later starts.

If the bundle loads native addons, link them into your app as well, as [Linking native addons](#linking-native-addons) describes.

## Linking native addons

react-native-bare-kit does not link the native addons that a worklet loads. Releases from 0.3.1 through 0.15.6 ran `bare-link` themselves, from the podspec on iOS and from a Gradle task before each Android build. Version 0.16.0 removed both steps along with its dependency on `bare-link`, so an app links its own addons.

Run [`bare-link`](https://github.com/holepunchto/bare-link) with the entry point of the worklet, the file that you pack into the bundle. It links the addons that the module graph of that entry point loads, for the hosts that a preset selects:

```sh
bare-link --preset ios --out ios/addons worklet.js
bare-link --preset android --out android/app/src/main/jniLibs worklet.js
```

Here `ios/addons` and `android/app/src/main/jniLibs` are directories of your own app project. The `ios` preset targets `ios-arm64`, `ios-arm64-simulator`, and `ios-x64-simulator`. The `android` preset targets `android-arm`, `android-arm64`, `android-ia32`, and `android-x64`. On iOS the output is one `.xcframework` bundle per addon, which you embed in the app target. On Android it is one `.so` library per addon and ABI, in a directory named for the ABI, which belongs in the `jniLibs` of the app, and you add any `.jar` library that an addon ships as a dependency. Pack the worklet with `bare-pack --linked` so that addons resolve to the linked libraries, as [Bundle a Bare app](/bare/how-to/run-on-native/bundle-a-bare-app) describes.

The native projects of the library also already include two directories in the build, without further configuration: any `.xcframework` bundle in its `ios/addons` directory, and any `.so` or `.jar` library in its `android/src/main/addons` directory. The package does not ship these directories, and `bare-link` creates them. Point `--out` at them to link without changing your own native projects:

```sh
bare-link --preset ios --out node_modules/react-native-bare-kit/ios/addons worklet.js
bare-link --preset android --out node_modules/react-native-bare-kit/android/src/main/addons worklet.js
```

These directories are inside `node_modules`, so reinstalling the library clears them. Run the commands from a `postinstall` script of the app to restore them:

```json
{
  "scripts": {
    "postinstall": "npm run link:ios && npm run link:android",
    "link:ios": "bare-link --preset ios --out node_modules/react-native-bare-kit/ios/addons worklet.js",
    "link:android": "bare-link --preset android --out node_modules/react-native-bare-kit/android/src/main/addons worklet.js"
  },
  "devDependencies": {
    "bare-link": "^4.0.1"
  }
}
```

## Bundled Bare version

A worklet runs the Bare that the kit embeds, not the Bare installed on your machine. The react-native-bare-kit package contains prebuilt bare-kit libraries for iOS and Android, which its `CMakeLists.txt` fetches from a fixed bare-kit release when the package is published. Versions 0.15.6 and 0.16.0 use the bare-kit 2.5.4 prebuilds, and bare-kit 2.5.4 and 2.5.5 both embed Bare 1.33.4, so a worklet in either version runs Bare 1.33.4. Bare features added after 1.33.4 are not available in a worklet until a bare-kit release embeds a newer Bare and a react-native-bare-kit release uses that bare-kit.

## Error handling

A worklet runs as a thread inside the host process, so it follows Bare's default handling of uncaught errors: an uncaught exception or unhandled promise rejection in worklet JavaScript is printed to `stderr` and the process is aborted. Because the worklet shares the host's process, this takes the **host** down with it. This is by design.

To keep a worklet error from aborting the host, register an `uncaughtException` (and/or `unhandledRejection`) listener inside the worklet. Adding a listener overrides the default abort and lets the worklet decide how to respond:

```js
Bare.on('uncaughtException', (err) => {
  // The host no longer aborts. Report the error to the host (for example over
  // BareKit.IPC) and exit or recover as appropriate.
  console.error(err)
})
```

The handler runs inside the worklet, not in the host, so the host cannot catch a worklet exception directly. Surface it yourself, for example by sending a message over IPC from the handler before the worklet exits. See the [`uncaughtException`](/bare/reference/bare/runtime#uncaughtexception-err) and [`unhandledRejection`](/bare/reference/bare/runtime#unhandledrejection-reason-promise) events.

## Logging

`console.*` calls inside the worklet write to the system log (via [`liblog`](https://github.com/holepunchto/liblog)) under the `bare` identifier, so worklet output shows up in the platform's native logging tools.
