[`bare-make`](https://github.com/holepunchto/bare-make) — Opinionated build system generator based on CMake.

```sh
npm i bare-make
```

## Usage

Like CMake, builds happen in three steps: You first generate a build system, then run the build system, and finally install the built artefacts. To perform the steps programmatically from JavaScript, do:

```js
const make = require('bare-make')

await make.generate()
await make.build()
await make.install()
```

The steps can also be performed interactively from the command line using the included CLI:

```console
bare-make generate
bare-make build
bare-make install
```

### Testing

To run tests for projects that use [`enable_testing()`](https://cmake.org/cmake/help/latest/command/enable_testing.html#command:enable_testing) and [`add_test()`](https://cmake.org/cmake/help/latest/command/add_test.html#command:add_test), do:

```js
await make.test()
```

Tests can also be run from the command line:

```console
bare-make test
```

### Environment

Programs built with some toolchains need environment changes to run. For example, the macOS, Linux, and Windows toolchains add the directory of `llvm-symbolizer`, which the sanitizers use to print readable reports, to `PATH`. `bare-make test` applies these changes automatically, but programs you run outside of CTest, such as a JavaScript test suite that loads an addon, must apply them themselves. Added in v2.1.0: to get the variables to set, do:

```js
const env = await make.test.env()
```

`env` maps each variable that the test launcher adds or changes to its resolved value. For `PATH` the value is the complete resolved list, not only the added directory. The variables can also be printed from the command line as `NAME=value` lines:

```console
bare-make test env
```

`test.env()` reads the build tree, so call it after `generate()`. It rejects with `ENV_FAILED` if there is no build tree at `build`. A build tree generated by a version before v2.1.0 records no test launcher, so its result is empty until you generate it again.

To record the launcher, `generate()` sets `CMAKE_PROJECT_INCLUDE` itself. A `CMAKE_PROJECT_INCLUDE` entry in `define` is kept and runs first, so it can change the launcher that is recorded.

### Toolchain

`bare-make` ships the tools it drives. It depends on `cmake-runtime`, `ninja-runtime`, `llvm-runtime`, and `nasm-runtime`. Changed in v2.0.0: the macOS, iOS, Linux, and `win32` targets use the Clang from `llvm-runtime` and, for the targets that assemble with NASM, the NASM from `nasm-runtime`, rather than a Clang and NASM found on the machine. Version 1.x used a Clang it found on the machine, such as Apple Clang on macOS. The Android targets still use the Android NDK, and the MinGW targets still use a MinGW compiler found on `PATH`.

The toolchain files locate `llvm-runtime` and `nasm-runtime` by running `node`, so `node` must be on `PATH` when you generate a build system for a target that uses them, including when `bare-make` itself runs on Bare. Without it, `generate()` rejects with `GENERATE_FAILED`, and CMake prints that it cannot find `node`, which it needs to resolve `llvm-runtime`. Version 1.x had no such requirement.

Added in v2.1.0: the `wasi-wasm32` target, selected with `platform: 'wasi'` and `arch: 'wasm32'` (`--platform wasi --arch wasm32` on the command line). The target comes from `cmake-toolchains` v2.1.0, which `bare-make` v2.1.0 is the first release to require. With an earlier `cmake-toolchains`, such as the one `bare-make` v1.8.0 uses, `generate()` rejects it with `UNKNOWN_TOOLCHAIN`. The target needs the optional `wasi-sysroot` package to be installed, and without it `generate()` rejects with `GENERATE_FAILED`. Executables built for it get the `.wasm` suffix.

Changed in v2.1.0, also through `cmake-toolchains` v2.1.0: the musl targets need the optional `musl-sysroot` package to be installed. They are selected with `environment: 'musl'`, or `'muslsf'` for the soft-float mips and mipsel targets. Earlier versions of `cmake-toolchains` needed a musl cross compiler, such as `x86_64-linux-musl-cc`, on `PATH`.

### Compiler and linker flags

`generate()` passes the flags it adds, such as those for `sanitize`, `fuzz`, `color`, and the frame pointer of `debug` builds, through the `CFLAGS`, `CXXFLAGS`, and `LDFLAGS` environment variables. Changed in v2.0.0: version 1.x set the `CMAKE_C_FLAGS` and linker flag cache entries instead. This has three effects:

- Flags already in those variables when you call `generate()` are kept, and the flags `bare-make` adds are appended. In version 1.x the cache entries replaced them.
- The compiler flags apply to C and C++. In version 1.x they applied to C only.
- CMake reads the variables when it first configures a build tree. Calling `generate()` again on an existing tree with a different `sanitize` value, or with `debug` turned on, leaves its compiler and linker flags as they were, although the build type still changes. Set `cache` to `false`, or pass `--no-cache`, to configure the tree again with the new flags. In version 1.x the flags changed on every call.

When the target platform is `win32`, `sanitize` also passes `/OPT:NOICF` to the linker, because identical code folding merges identical globals, which AddressSanitizer then reports as one-definition-rule violations. Added in v2.0.1.

### Functions

#### `build(opts?: BuildOptions): Promise<void>`

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `opts?` | `BuildOptions` | — | Options; `build` defaults to `'build'` (unset when `preset` is set), `parallel` to `0`, and `clean` and `verbose` to `false`. |

**Throws**

- `BUILD_FAILED` — the build exits with a non-zero status.

#### `generate(opts?: GenerateOptions): Promise<void>`

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `opts?` | `GenerateOptions` | — | Options; `source` defaults to `'.'`, `build` to `'build'`, `platform` and `arch` to the host, `cache` to `true`, and the build-type flags (`debug`, `fuzz`, `withDebugSymbols`, `withMinimalSize`, `verbose`) to `false`. |

**Throws**

- `UNKNOWN_TOOLCHAIN` — no toolchain is available for the resolved `platform`-`arch` target.
- `GENERATE_FAILED` — build system generation exits with a non-zero status.

#### `install(opts?: InstallOptions): Promise<void>`

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `opts?` | `InstallOptions` | — | Options; `build` defaults to `'build'`, `prefix` to `'prebuilds'`, and `link`, `strip`, and `verbose` to `false`. |

**Throws**

- `INSTALL_FAILED` — the install exits with a non-zero status.

#### `test(opts?: TestOptions): Promise<void>`

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `opts?` | `TestOptions` | — | Options; `build` defaults to `'build'`, `timeout` to `30` seconds, `parallel` to `-1`, and `verbose` to `false`. |

**Throws**

- `TEST_FAILED` — one or more tests fail.

#### `test.env(opts?: EnvOptions): Promise<Record<string, string>>`

Resolve the environment variables that programs from the build tree need to run, as changed by the test launcher. Added in v2.1.0.

**Parameters**

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `opts?` | `EnvOptions` | — | Options; `build` defaults to `'build'`. |

**Returns** `Promise<Record<string, string>>` — The changed variables with their resolved values.

**Throws**

- `ENV_FAILED` — the build tree does not exist or the environment cannot be resolved.

## CLI

#### `bare-make generate [flags]`

Flags include:

```console
--source|-s <path>                   The path to the source tree
--build|-b <path>                    The path to the build tree
--platform|-p <name>                 The operating system platform to build for
--arch|-a <name>                     The operating system architecture to build for
--simulator                          Build for a simulator
--environment|-e <name>              The environment to build for
--no-cache                           Disregard the build variable cache
--preset <name>                      The preset to use
--debug|-d                           Configure a debug build
--with-debug-symbols                 Configure a release build with debug symbols
--with-minimal-size                  Configure a release build with minimal size
--sanitize <name>                    Enable a sanitizer
--fuzz                               Configure for fuzzing
--define|-D <var>[:<type>]=<value>   Create or update a build variable cache entry
--no-color                           Disable colored output
--verbose                            Enable verbose output
--help|-h                            Show help
```

#### `bare-make build [flags]`

Flags include:

```console
--build|-b <path>        The path to the build tree
--target|-t <name>       The target to build
--clean|-c               Clean before building
--parallel|-j <number>   Build in parallel using the given number of jobs
--preset <name>          The preset to use
--verbose                Enable verbose output
--help|-h                Show help
```

#### `bare-make install [flags]`

Flags include:

```console
--build|-b <path>        The path to the build tree
--prefix|-p <path>       The prefix to install to
--component|-c <name>    The component to install
--link|-l                Link rather than copy the files
--strip|-s               Strip before installing
--parallel|-j <number>   Install in parallel using the given number of jobs
--verbose                Enable verbose output
--help|-h                Show help
```

#### `bare-make test [flags]`

Flags include:

```console
--build|-b <path>        The path to the build tree
--timeout <seconds>      The default test timeout
--parallel|-j <number>   Run tests in parallel using the given number of jobs
--preset <name>          The preset to use
--verbose                Enable verbose output
--help|-h                Show help
```

#### `bare-make test env [flags]`

Print the environment that tests run with, one `NAME=value` line per variable. Added in v2.1.0. Flags include:

```console
--build|-b <path>   The path to the build tree
--help|-h           Show help
```

- Builds on `bare-env`, `bare-fs`, `bare-os`, and `bare-path`.
- It drives CMake with Ninja and Clang for a consistent toolchain across platforms, while staying plain CMake underneath so you can eject.

- v2.0.0 dropped `bare-process`. The JavaScript API still runs on Bare, but the CLI is a Node.js script: run through `bare`, `bin.js` fails with `MODULE_NOT_FOUND` for `process`, which v1.8.0 resolved through `bare-process`.
