`pear --menu` opens an interactive, terminal-driven menu for the whole CLI: pick a command from a filterable list, fill in its arguments and flags as a real form, confirm, and Pear runs exactly what typing the equivalent command would have run. It's the fastest way to discover what a command needs without leaving your terminal to check [the reference](/pear/reference/pear/cli).

<Callout type="info">
Requires **Pear 3.2.0 or newer**—run [`pear versions`](/pear/reference/pear/cli#pear-versions) to check what you're on. Not available on 3.1.x or earlier. The command groups and group help described below need **Pear 3.7.0**; on 3.2.0 to 3.6.x the menu is one flat list.
</Callout>

## Launch the menu

```console skip="interactive"
pear --menu
```

<Callout type="warning">
This needs an interactive terminal (a TTY). Run it from a script, a CI job, or any other non-interactive shell and it exits immediately with `pear --menu requires an interactive terminal`.
For scripts and automation, use the command's flags directly instead—see [Scripting with `--json`](/pear/reference/pear/cli#json-output).
</Callout>

## Find a command

![The interactive menu's command list, grouped into Ship, Install & inspect, Release, Network, and a collapsed Platform group](/pear-menu-find-command.png)

The menu opens on a list of every command, grouped by what you are doing with it:

- **Ship**—`touch`, `stage`, `seed`, `build`, and `make`: create a link, put files on it, share it, and package desktop installers (`build`) or CLI apps (`make`) that update from it. For a desktop release, build before you stage, as in [Deploy your application](/pear/how-to/operate-an-app/manual-deployment/deployment).
- **Install & inspect**—`info`, `changelog`, `dump`, and `install`: look at a link, or put it on this machine. None of them changes the link.
- **Release**—`provision` and the `multisig` subcommands: promote a build to production under a signing quorum.
- **Network**—`blind-relay`, `blind-peer`, and `identity`: help other peers connect and stay seeded.
- **Platform**—`sidecar shutdown`, `cores`, `gc cores`, `data dht`, `data multisig`, `versions`, and `help`: the local sidecar, storage, and versions. This group starts collapsed because you rarely need it to ship an app.

Move to a command and press `enter` to choose it. Press `enter` on a group header to collapse or expand the group. The commands keep their full names under a group, so `multisig sign` is still `pear multisig sign`.

Each group has a help panel that explains how its commands fit together. Press `F1` or `ctrl+k` on a group to open it, and `esc` to close it.

![The help panel for the Ship group, which explains how touch, stage, seed, and build fit together](/pear-menu-group-help.png)

To narrow the list, press `/` and type. The list keeps the header of each group that still has a match, so you can see where a command lives. Press `enter` to stop typing and keep the filter, then `enter` again to choose a command.

- `/` — start filtering
- `enter` — choose the highlighted command, or collapse or expand the highlighted group; while typing a filter, stop typing
- `←` / `→` — collapse or expand the group
- `F1` or `ctrl+k` — open the help panel for the group
- `esc` — close the help panel, or clear the filter
- `ctrl+c` — quit

## Fill in the form

![The interactive menu's generated form for `pear build`, one field per argument and flag](/pear-menu-fill-form.png)

Once you pick a command, the menu builds a real form from its arguments and flags—one field per parameter, using the same descriptions and defaults documented on the [CLI reference](/pear/reference/pear/cli).
Fill in what you need, leave the rest at their defaults, and confirm to run the command.
The result is identical to typing the equivalent `pear <command> --flags` yourself—the menu is a different way to assemble the same call, not a different tool.

- `tab` — move between fields
- `ctrl+s` — submit and run the command
- `ctrl+c` — cancel

Forms with more fields than fit on screen also show `↕ scroll`.

From Pear 3.3.0 each field also carries a hint covering that argument or flag's constraints, how it interacts with the others, and how it fails—for example that `pear stage --dry-run` does not guard `--truncate`, or that `--ignore` accepts glob patterns while `--only` matches by path prefix. These hints appear only in the menu; `pear help <command>` shows the one-line descriptions without them.

## When to use it

Use the menu when you're exploring a command's flags—new to Pear, or new to a command you don't use often—and don't want to context-switch to [the reference](/pear/reference/pear/cli) to check a flag's spelling or default.
Use flags directly once you know the shape of the command you want, for scripts, CI, or anything else that needs to run non-interactively.
