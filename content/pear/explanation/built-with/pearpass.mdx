[PearPass](https://pass.pears.com) is an open-source, end-to-end encrypted password and identity manager built on Pear Runtime. Vaults are encrypted and stored on the user's own device and synced directly between that user's devices, with no central server holding the data. It ships as a desktop app for macOS, Linux, and Windows, a mobile app, and a browser extension, and the source for all three is public under the [`tetherto`](https://github.com/tetherto) GitHub organization.

That makes PearPass the Pear app whose architecture you can read rather than infer, which is why it's documented here. Keep one thing in mind while reading it: the desktop repository's README states that PearPass is **currently paused from active development**, so treat the code as a reference architecture, not a template to track.

## What PearPass is

- **Encrypted at rest.** Passwords, cards, secure notes, and custom fields are encrypted before they are written to disk, behind a master password.
- **Synced peer-to-peer.** Devices are paired with an invite; from then on vault changes replicate directly between them.
- **Offline first.** The vault is local, so it is readable with no network at all.
- **Three clients, one vault library.** Desktop, mobile, and the browser extension share the vault logic and differ in their host.

## What to learn from it

- **One core, three hosts, for real.** The vault library is written once and given a different *client* per platform. The desktop client runs in a Pear app; the mobile client runs on Bare inside React Native; the browser extension doesn't run the core at all and bridges to the desktop app instead. That is the [core / UI-host split](/p2p/explanation/how-the-stack-fits-together#apps-one-core-many-ui-hosts) applied to a product with unusual hosts.
- **Autobase as the sync layer.** PearPass doesn't implement sync. Each device is a writer in an Autobase, so "sync" is replication plus the Autobase view, and adding a device is a pairing invite. Part 2 of the [Getting started](/pear/getting-started) tutorial builds the same structure for a chat room.
- **Updates ride the same rails as data.** The desktop app's `pear-runtime-updater` pulls new versions from the swarm, exactly as [Release pipeline](/pear/explanation/deployment-releasing-apps-p2p) describes.
