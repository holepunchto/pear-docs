Welcome to the Pear. You can use this getting started guide to take you from zero to a small **Pear desktop** app you type yourself, then optionally add **on-disk history** and finally  **shipping with over-the-air updates** the way production Pear Electron apps do.

The walkthroughs mirror the architecture described in [Pear desktop application architecture](/explanation/pear-desktop-architecture) (and the production release story in [Release pipeline](/explanation/release-pipeline)) in thin slices:


| Step | Page | What you do |
| --- | --- | --- |
| 1 | [**Build a peer-to-peer chat**](/getting-started/chat) | Create five files: Electron shell, preload bridge, Bare worker with Hyperswarm, plain renderer. About 15 minutes. |
| 2 | [**Add persistence**](/getting-started/persist) | Append messages to a [Corestore](/reference/helpers/corestore) transcript and replay on launch. |
| 3 | [**Ship and update**](/getting-started/ship-and-update) | `pear touch` + `upgrade`, replace `electron/main.js` with `new Pear({ ... })`, `pear seed`, and `pear stage` (dry-run). Optional deeper reading: [deploy](/how-to/operate-an-app/deployment) / [build](/how-to/operate-an-app/build-desktop-distributables). |

<Callout type="info">

For the conceptual picture of workers, storage, and OTA in any Electron repo, read [Pear desktop application architecture](/explanation/pear-desktop-architecture). For how **stage → provision → multisig** fits together, read [Release pipeline](/explanation/release-pipeline).

</Callout>

## Before you start 

Across the steps you will use:

- [Node.js](https://nodejs.org/) ≥ 22.17 and npm ≥ 10.9
- A POSIX-style terminal (macOS, Linux, or Windows with WSL)
- An IDE or text editor

Individual pages list anything extra (for example extra npm packages on the persistence step).
