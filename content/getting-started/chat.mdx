This is **part 1 of 3** in the [getting started path](/getting-started). You will build a peer-to-peer desktop chat with Pear. By the end you will have an Electron app that finds peers on the public [distributed hash table (DHT)](/reference/building-blocks/hyperdht) and exchanges messages with them. Next you can [add a local message log](/getting-started/persist), then [ship the app and wire over-the-air updates](/getting-started/ship-and-update).

The example mirrors the layout in [Pear desktop application architecture](/explanation/pear-desktop-architecture) — a typical Pear + Electron starter — in minimal slices:
1. Live Hyperswarm chat first
2. Persistence and deployment follow in [part 2](/getting-started/persist) and [part 3](/getting-started/ship-and-update).

## What you'll build

A small desktop window with a message list, a text input, and a peer counter. Two windows running on the same machine — or on a friend's machine on the other side of the world — can discover each other through the [DHT](/reference/building-blocks/hyperdht) and stream messages directly.

<Image

Each peer shows up under a six-character hex id derived from its public key — that's what your worker emits when a new peer connects.

The four moving parts you'll use to build the chat:

- **[`pear-runtime`](/reference/runtime)** — the library that lets a JavaScript host (Electron in this case) embed [Bare](/explanation/runtime-and-languages) workers.
- **The [Bare worker](/explanation/runtime-and-languages)** — a separate process that owns the peer-to-peer code. Acts as a local backend for the renderer.
- **[Hyperswarm](/reference/building-blocks/hyperswarm)** — finds peers on a topic and gives you a connection.
- **[The Electron preload bridge](#add-the-preload-bridge)** — the only door between the browser-style renderer and the worker.

## Before you start

You need:

- [Node.js](https://nodejs.org/) ≥ 22.17 and npm ≥ 10.9
- A POSIX-style terminal (macOS, Linux, or Windows with WSL)
- An IDE or text editor

## Project layout

You'll create five files in a fresh folder:

```text
chat-app/
├─ package.json        # app metadata, scripts, npm dependencies
├─ electron/
│  ├─ main.js          # CommonJS — window + worker + IPC
│  └─ preload.js       # CommonJS — exposes window.chat to the renderer
├─ renderer/
│  ├─ index.html       # layout + Tailwind CDN script
│  └─ app.js           # DOM + window.chat send/receive
└─ workers/
   └─ main.mjs         # ESM — Hyperswarm (Bare argv/IPC)
```

### Set up the project

#### Create the folder and initialize it

Create the folder and initialize it with `npm init -y` to create a `package.json` file:

```bash
mkdir chat-app   # project root
cd chat-app
npm init -y      # writes a starter package.json you will replace next
```

#### Update the `package.json`

Open the generated `package.json` and replace it with the following:

```json
{
  "name": "chat-app",
  "version": "1.0.0",
  "main": "electron/main.js",
  "type": "commonjs",
  "scripts": {
    "start": "cross-env ELECTRON_RUN_AS_NODE= electron ."
  },
  "dependencies": {
    "b4a": "^1.6.7",
    "hyperswarm": "^4.17.0",
    "pear-runtime": "^1.1.3"
  },
  "devDependencies": {
    "cross-env": "^7.0.3",
    "electron": "^41.5.1"
  }
}
```

- **[b4a](https://www.npmjs.com/package/b4a)** — binary buffer helpers (`Uint8Array`) used in the Bare worker for topics and wire data.
- **[hyperswarm](https://www.npmjs.com/package/hyperswarm)** — finds and connects peers over the DHT so messages flow between chat windows.
- **[pear-runtime](https://www.npmjs.com/package/pear-runtime)** — loads the Pear runtime in the Electron main process so you can spawn and talk to the Bare worker.
- **[electron](https://www.npmjs.com/package/electron)** — the desktop shell that runs the main process, window, and preload in this tutorial (listed under `devDependencies` because the app logic does not import it from Node).
- **[cross-env](https://www.npmjs.com/package/cross-env)** — makes the `start` script clear **`ELECTRON_RUN_AS_NODE`** before launching Electron (see callout below). This is unrelated to **`TextEncoder`** / **`pear-runtime`** — it only avoids a bad default in some IDE terminals.

#### Install the dependencies

```bash
npm install   # downloads deps listed in package.json into node_modules/
```

You should see something like:

```text
# example npm output (versions and counts vary)
added 185 packages, and audited 186 packages in 3s

17 packages are looking for funding
  run `npm fund` for details

found 0 vulnerabilities
```
<Callout type="info">

The renderer loads [Tailwind CSS v4](https://tailwindcss.com/) in the browser from a CDN — the [`@tailwindcss/browser`](https://www.npmjs.com/package/@tailwindcss/browser) package served by jsDelivr — in `index.html`, so you do not add Tailwind as an npm dependency for this walkthrough.

</Callout>

<Callout type="info">

Some terminals (including some embedded in IDEs) export **`ELECTRON_RUN_AS_NODE=1`**. That makes the Electron binary behave like plain Node, so `require('electron')` in `electron/main.js` resolves to the **npm installer stub** (a path string) instead of the real API and **`app.whenReady`** throws. The **`cross-env ELECTRON_RUN_AS_NODE=`** prefix in **`npm start`** sets that variable to empty for the child process only. If your shell never sets it, you can simplify the script to **`electron .`** and drop the **`cross-env`** devDependency.

</Callout>

The Bare runtime ships as a prebuilt binary inside [`bare-sidecar`](https://www.npmjs.com/package/bare-sidecar) (a transitive dep of [`pear-runtime`](https://www.npmjs.com/package/pear-runtime)), so there's nothing to compile.

This guide uses **`pear-runtime` ^1.1.3**, which pulls **`bare-sidecar` ^0.4** and exposes **`TextEncoder`** in workers (see [part 2 — persist](/getting-started/persist)). The [**hello-pear-electron**](https://github.com/holepunchto/hello-pear-electron) template currently lists **`pear-runtime` ^1.0.1**, which stays on **`bare-sidecar` ^0.3** and does **not** ship **`TextEncoder`**. **`pear-runtime` 1.1.0** and **1.1.1** are still on **`bare-sidecar` ^0.3**; use **^1.1.3** to match this guide.

</Step>

### Write the worker

The worker is where all the peer-to-peer code lives. It runs in a separate Bare process — not in Electron. That keeps the renderer free of native modules and the main process free of swarm logic.

Create `workers/main.mjs`. The `.mjs` (Module JavaScript) extension is important: it forces the file to load as an ES module regardless of what `"type"` your `package.json` declares.

```js
import Hyperswarm from 'hyperswarm' // topic swarms / DHT discovery
import b4a from 'b4a' // encode/decode binary topic and payloads

// Topic hex string comes from Electron via Bare.argv (see main process step)
const topic = b4a.from(Bare.argv[2], 'hex')
const swarm = new Hyperswarm()
const conns = [] // active peer sockets

swarm.on('connection', (conn) => {
  const id = b4a.toString(conn.remotePublicKey, 'hex').slice(0, 6) // short display id
  conns.push(conn)
  Bare.IPC.write(JSON.stringify({ type: 'peers', count: conns.length }))

  conn.on('data', (data) => {
    Bare.IPC.write(
      JSON.stringify({ type: 'message', from: id, text: b4a.toString(data) })
    )
  })

  conn.on('error', () => {}) // ignore transient socket errors
  conn.once('close', () => {
    conns.splice(conns.indexOf(conn), 1)
    Bare.IPC.write(JSON.stringify({ type: 'peers', count: conns.length }))
  })
})

// Text from Electron main → broadcast to every peer
Bare.IPC.on('data', (data) => {
  const text = b4a.toString(data)
  for (const conn of conns) conn.write(text)
})

Bare.IPC.write(
  JSON.stringify({
    type: 'message',
    from: 'system',
    text: 'Joining Hyperswarm… (first connect can take a few seconds)'
  })
)

await swarm.join(topic, { client: true, server: true }).flushed()
Bare.IPC.write(JSON.stringify({ type: 'ready' }))
```

A few things to notice:

- [`Bare.IPC`](/reference/runtime#running-workers) is the worker's pipe back to the Electron main process. Anything you write to `Bare.IPC` shows up as a `'data'` event on the worker handle in Electron.
- The **`Joining Hyperswarm…`** line goes out **before** [`swarm.join(...).flushed()`](https://github.com/holepunchto/hyperswarm) finishes. The first DHT attach can take several seconds; without that line the log stays empty and the app looks stuck.
- [`Bare.argv`](/reference/api#bare-argv) is the array of arguments the main process passes when it spawns the worker. `Bare.argv[2]` is the first user-supplied arg — that's where the topic lives. You'll [wire that up next](#wire-up-electrons-main-process).
- The worker depends on nothing Bare-specific beyond `Bare.IPC` and `Bare.argv`. `Hyperswarm` and `b4a` are normal npm packages that work in both Bare and Node.

<Callout type="info">
**Want a closer look at Hyperswarm?** [Connect to many peers by topic with Hyperswarm](/how-to/connect-to-peers/connect-to-many-peers-by-topic-with-hyperswarm) walks through the swarm-on-a-topic pattern in isolation, without Electron or Bare in the picture.
</Callout>

<Callout type="info">
The worker uses ESM (`import`) because that's Bare's recommended convention for new code. The Electron files in the next steps use CommonJS (`require`) because that's what most Electron projects ship with.

The two coexist cleanly thanks to the file-extension split: anything ending in `.mjs` is ESM, anything ending in `.js` follows the `package.json` `"type"` field — which we set to `"commonjs"` above. If you're curious about how this works, read [Runtime and languages](/explanation/runtime-and-languages).
</Callout>

</Step>

### Wire up Electron's main process

The main process creates the window and starts the worker after [`did-finish-load`](https://www.electronjs.org/docs/latest/api/web-contents#event-did-finish-load). [`PearRuntime.run()`](/reference/runtime#running-workers) does most of the heavy lifting; everything else is plumbing.

The preload script (next step) subscribes to `chat:from-worker` as soon as it loads and **queues** JSON events until `renderer/app.js` calls `onMessage`, so the first worker lines (including the **Joining Hyperswarm…** line and Corestore replay in [part 2 — persist](/getting-started/persist)) are never dropped while Tailwind or other head scripts slow the page down.

Create `electron/main.js`:

```js
const { app, BrowserWindow, ipcMain } = require('electron')
const path = require('path')
const os = require('os')
const crypto = require('crypto')
const PearRuntime = require('pear-runtime') // spawn Bare workers from Node

// Deterministic per-username topic so two local windows meet, others stay separate by default
const topic = crypto
  .createHash('sha256')
  .update('pear-getting-started-chat:' + os.userInfo().username)
  .digest('hex')

let worker = null // Bare worker handle (duplex stream)

function createWindow() {
  const win = new BrowserWindow({
    width: 480,
    height: 600,
    webPreferences: {
      preload: path.join(__dirname, 'preload.js'), // defines window.chat in the renderer
      contextIsolation: true,
      sandbox: true,
      nodeIntegration: false
    }
  })

  const workerPath = path.join(__dirname, '..', 'workers', 'main.mjs')

  win.webContents.once('did-finish-load', () => {
    worker = PearRuntime.run(workerPath, [topic]) // argv[2] in the worker is the topic hex

    worker.on('data', (data) => {
      if (!win.isDestroyed()) win.webContents.send('chat:from-worker', data.toString())
    })

    worker.stderr.on('data', (data) => {
      console.error('[worker]', data.toString())
    })

    worker.stdout.on('data', () => {}) // drain; Bare can block if stdout fills
  })

  win.loadFile(path.join(__dirname, '..', 'renderer', 'index.html'))
}

app.whenReady().then(() => {
  ipcMain.handle('chat:send', (_evt, text) => {
    if (worker) worker.write(Buffer.from(text)) // forwarded to Bare.IPC in the worker
  })
  createWindow()
})

app.on('window-all-closed', () => {
  if (worker) worker.destroy()
  app.quit()
})
```

A few things happen here:

- The worker starts on **`did-finish-load`**; preload buffering covers the gap until **`onMessage`** runs.
- [`PearRuntime.run(workerPath, [topic])`](/reference/runtime#running-workers) is the static method on [`pear-runtime`](/reference/runtime) that spawns a Bare worker. The second argument becomes the worker's `Bare.argv` — that's how the topic reaches the worker. The call returns a duplex stream whose other end is `Bare.IPC` inside the worker.
- The topic is derived from the OS username with a fixed prefix. Two windows on **your** machine find each other immediately while staying isolated from other readers running the same example. Change the prefix string `'pear-getting-started-chat:'` to share a private room with a friend.
- This is the simplest form of [`pear-runtime`](/reference/runtime). The full [`new Pear({ ... })`](/reference/runtime#instantiate) constructor — with the OTA updater and a shared [Corestore](/reference/helpers/corestore) — is what you use once you start [shipping updates](/getting-started/ship-and-update) (covered in part 3 of this path).

</Step>

### Add the preload bridge

The renderer runs in a sandboxed browser context with `contextIsolation: true`. It can't talk to the worker directly. The preload script is a tiny adapter that exposes a `window.chat` object the renderer can use.

#### Create `electron/preload.js`

```js
const { contextBridge, ipcRenderer } = require('electron')

const pending = []
let onMessageListener = null

ipcRenderer.on('chat:from-worker', (_evt, payload) => {
  let event
  try {
    event = JSON.parse(payload)
  } catch {
    return
  }
  if (onMessageListener) onMessageListener(event)
  else pending.push(event)
})

contextBridge.exposeInMainWorld('chat', {
  send(text) {
    return ipcRenderer.invoke('chat:send', text) // → ipcMain.handle in main
  },
  onMessage(listener) {
    onMessageListener = listener
    for (const event of pending.splice(0, pending.length)) listener(event)
  }
})
```

[`contextBridge.exposeInMainWorld`](https://www.electronjs.org/docs/latest/api/context-bridge#contextbridgeexposeinmainworldapikey-api) puts a single `chat` object on the renderer's `window` with two methods:
* `send(text)` ships a message to the worker through the main process
* `onMessage(listener)` registers the callback and **replays** any worker lines that arrived while the page was still loading

</Step>

### Build the renderer

The renderer is a normal HTML page. Nothing here is Pear-specific — it calls `window.chat.send` and `window.chat.onMessage` to send and receive messages from the worker.

#### Create `renderer/app.js`

This file sets up the DOM and listens for messages from the worker. When the worker sends a message, it appends it to the log. When the user types a message and presses Enter, it sends the message to the worker.

```js
const log = document.getElementById('log')
const peers = document.getElementById('peers')
const input = document.getElementById('input')

const fromColor = {
  system: 'text-zinc-500 italic',
  you: 'text-emerald-400 font-medium',
  peer: 'text-sky-400 font-medium'
}

function append(from, text) {
  const row = document.createElement('div')
  row.className = 'flex gap-2 items-baseline'

  const fromEl = document.createElement('span')
  fromEl.className = fromColor[from] ?? fromColor.peer
  fromEl.textContent = from + ':'

  const textEl = document.createElement('span')
  textEl.textContent = text

  row.append(fromEl, textEl)
  log.appendChild(row)
  log.scrollTop = log.scrollHeight // keep latest line visible
}

// JSON lines from the worker, forwarded by preload → main → here
window.chat.onMessage((event) => {
  if (event.type === 'peers') peers.textContent = event.count
  else if (event.type === 'message') append(event.from, event.text)
  else if (event.type === 'ready') append('system', 'connected to swarm')
})

input.addEventListener('keydown', (e) => {
  if (e.key !== 'Enter' || !input.value) return
  const text = input.value
  input.value = ''
  append('you', text)
  window.chat.send(text) // preload → main → worker Bare.IPC
})
```

## What you built

A peer-to-peer desktop chat that runs without a server. Each piece you wrote maps to one concept:

| File | What it does | Pear concept |
|---|---|---|
| `package.json` | Declares Electron, Hyperswarm, Pear runtime, **`cross-env`** (clears **`ELECTRON_RUN_AS_NODE`** in `npm start`) | The Pear stack you embed into a JS host |
| `workers/main.mjs` | Hyperswarm + topic + connection handlers | Peer-to-peer code lives in a [Bare worker](/explanation/runtime-and-languages) |
| `electron/main.js` | `PearRuntime.run()` to spawn the worker | The worker is your local backend |
| `electron/preload.js` | `contextBridge.exposeInMainWorld` | The single door from renderer to worker |
| `renderer/*.{html,js}` | Plain DOM, no Pear imports | The view layer is a plain web page |
