<Callout type="warning">
Commit `[]` only once per drive, before its first release. After that, the action keeps `ci/snapshot.json` up to date. Never reset it to `[]`, and never commit it empty or as invalid JSON: `pear-ci` treats a file it can't parse as `[]`, so a stray comma or a leftover merge-conflict marker does the same damage as a reset. Publish each drive from one repository. If you move publishing to another repository, copy the latest `ci/snapshot.json` across instead of starting from `[]`.

A run that starts from `[]` against a drive that already has releases writes a second history under the same key. `pear-ci` 0.1.2 logs `[hypercore] conflict detected`, still exits with code 0, and the seeder's view of the drive drops to length 0. `pear-ci` 0.1.2 can't recover the drive from this state. To publish again, set a new `namespace`, commit `[]` for the new drive, and seed the new link that a dry run prints. A new namespace means a new `pear://` link, so you have to update the `upgrade` field and re-onboard users, as with a rotated primary key.
</Callout>
