Many Pear **Electron** repositories wrap **Electron Forge** (or similar) behind `package.json` scripts so day-to-day work stays predictable. This page lists **typical** script names and what they usually run; your project may rename them — read `package.json` locally.

<Callout type="info">

**Related:** [Build desktop distributables](/how-to/operate-an-app/build-desktop-distributables) and [`pear-runtime` — disabling updates](/reference/runtime#disabling-updates) match how sample desktop apps wire dev start (`--no-updates`) versus production updates.

</Callout>

## `npm start`

Starts the app in **development** mode. Sample repos often forward to `electron-forge start` with **`--no-updates`** so a seeded `pear://` link does not replace your working tree while you hack.

To exercise the OTA path locally, many templates support an explicit flag (for example `npm start -- --updates`).

## `npm run lint` / `npm run format`

Usually run **Prettier** and the **project linter** configured in `package.json` (`--check` vs `--write`). Exact tools vary — inspect `scripts` in your repo.

## `npm run package`

Runs **`electron-forge package`** (or equivalent) to produce a packaged app **without** full per-OS distributables — useful for a quick smoke test.

## `npm run make:linux`

Builds Linux artifacts (often `electron-forge package` plus a helper that produces an **AppImage** or your chosen format). Run on **Linux** or in CI with a Linux worker.

## `npm run make:darwin`

Runs **`electron-forge make --platform=darwin`** on **macOS** to produce `.app` bundles (and sometimes other artifacts depending on config).

## `npm run make:win32`

Runs **`electron-forge make --platform=win32`** on **Windows** to produce **MSIX** (or configured outputs). Requires Windows SDK and PowerShell 7+ on the build host.
