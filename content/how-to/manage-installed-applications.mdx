Pear keeps every installed application and its storage in one directory tree (described in [Storage and distribution](/explanation/storage-and-distribution)). To enumerate what's installed or to reset an app's data, the [Pear CLI](/reference/pear/cli) exposes two commands. Both run anywhere on the machine—they don't need a project directory.

<Callout type="info">
Installing applications from a `pear://` link is moving to a first-class [`pear install`](/reference/pear/cli#pear-install) command (preview it today with `npx pear-install pear://<key>`). See [Installing applications](/explanation/storage-and-distribution#installing-applications) for the model.
</Callout>

## List installed applications

Run `pear data apps` to see every application keyed by its `pear://` link, with the path to its on-disk storage:

```console skip="machine-state"
pear data apps
```

Output is a list of application keys and their storage paths:

```text skip="sample-output"
- pear://keet
    storage: ./pear/app-storage/by-dkey/197ea022b663edbedcf0b2a0fe44ebc99c21448cb46d375ec77d95de6e0a4c1a

- pear://runtime
    storage: ./pear/app-storage/by-dkey/50f2c1326de970da319534164017f23101c6badd5497a99045f8d9ef13978995

- pear://38cna455dbguiatg46z98cs7b6p4t4sh6hskozuhmipmpkxmmeuy
    storage: ./pear/app-storage/by-dkey/be6ff2fc20eb691af1ff7b90d5848ee1e22d2fe4fab031900e1014e224f659ab
```

`pear://runtime` (and any `pear://<alias>`) is the Pear platform itself; everything else is a third-party application. See the [`pear data` reference](/reference/pear/cli#pear-data) for the full subcommand and flag list.

## Reset an application's storage

There is no `pear uninstall`. The closest equivalent is `pear drop`, which **permanently deletes** an application's local storage:

```console skip="destructive"
pear drop app pear://<application-link>
```

The command prompts for confirmation before deleting anything—you must type `RESET` (uppercase) to proceed.

This is destructive. Anything stored only locally (chat history, drafts, user-generated content) is gone after the command completes. Use it when you want a clean slate for testing or to recover from a corrupt drive—see the [`pear drop` reference](/reference/pear/cli#pear-drop) for the full flag list.

The application binary itself stays available on the swarm; only the storage tied to your local copy is dropped. Re-running the application against the same link rebuilds an empty storage.
