Since Pear v3, applications are installed with [`pear install`](/reference/pear/cli#pear-install) directly into your operating system's application folder, and each app keeps its peer-to-peer data in a local corestore (described in [Storage and distribution](/explanation/storage-and-distribution)). This guide covers finding what's installed and resetting an app's storage.

<Callout type="info">
`pear data apps` and `pear drop` were removed in Pear v3. Applications now live in the OS application folder, and local corestore data is cleared with [`pear gc cores`](/reference/pear/cli#pear-gc).
</Callout>

## Find installed applications

`pear install pear://<key>` places apps in the standard OS location:

- **macOS** — apps in `/Applications`, binaries in `/usr/local/bin`
- **Linux** — apps in `~/Applications`, `~/AppImages`, or `~/.local/bin`; binaries in `~/.local/bin`

Browse that folder to see what's installed, the same as any native application. To inspect a specific application, pass its link to [`pear info`](/reference/pear/cli#pear-info):

```console skip="machine-state"
pear info pear://<application-link>
```

Run `pear info` with no argument to view Pear platform information instead.

## Reset an application's storage

There is no `pear uninstall`—remove the app from your OS application folder to uninstall it. To wipe an application's **local peer-to-peer storage** (its corestore) without touching the copy on the swarm, use [`pear gc cores`](/reference/pear/cli#pear-gc) with the app link:

```console skip="destructive"
pear gc cores pear://<application-link>
```

This clears the corestore cores tied to your local copy. Anything stored only locally (chat history, drafts, user-generated content) is gone afterwards. Use it when you want a clean slate for testing or to recover from a corrupt drive.

The application binary itself stays available on the swarm; only the local storage is cleared. Re-running the application against the same link rebuilds an empty storage.
