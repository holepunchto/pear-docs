# Pear Docs

Official documentation for the [Pear](https://pears.com) platform by Holepunch.

* Source code and content of the docs website.
* Automation scripts for link checking and documentation quality.

The docs website is a static site generated via SSG from a Next.js + **Fumadocs** application.

## Installation

### Prerequisites

* Node.js >= 20.0.0
* `npm` >= 10.0.0

### Initialize submodules

The `@tetherto/docs-seo-*` packages live in the [`tetherto/docs-template`](https://github.com/tetherto/docs-template) git submodule under `src/lib/docs-template/packages/`. They are wired up as npm workspaces, so `npm install` resolves them locally — no GitHub Packages auth needed for ordinary installs.

Clone with the submodule in one step:

```bash
git clone --recurse-submodules git@github.com:holepunchto/pear-docs.git
cd pear-docs
npm install
```

If you already cloned without `--recurse-submodules`:

```bash
git submodule update --init --recursive
npm install
```

#### Staying in sync

The `src/lib/docs-template` pointer moves when the SEO/OG packages get a new release. To auto-update it on every `git pull` or `git checkout`, set this once per clone:

```bash
git config submodule.recurse true
```

If you skip this and see `M src/lib/docs-template` in `git status` after a pull, run `git submodule update --recursive`, then `npm install` if `package-lock.json` also changed.

### Set up `.env`

1. Create `.env` from the example:

   ```bash
   cp .env.example .env
   ```

2. Fill in any required values (see comments in `.env.example`).

### Install dependencies

```bash
npm install
```

## Development

Run dev server:
```bash
npm run dev
```

Check broken internal links:
```bash
npm run check:internal-links
```

Check broken external links:
```bash
npm run check:external-links
```

Audit cross-link coverage and orphan pages (informational; `--strict`
fails the build on coverage <50% for high-mention canonical terms or any
page with <2 inbound links):
```bash
npm run check:cross-links
# or enforce thresholds in CI:
npm run check:cross-links -- --strict
```

Check that legacy URL redirects still resolve to live pages:
```bash
npm run check:redirects        # requires a build first; reads out/_redirects + stubs
```

Check that every page's `docType` frontmatter matches the Diátaxis quadrant
it lives in (a how-to in `content/how-to/`, an explanation in
`content/explanation/`, etc.):
```bash
npm run check:doctypes
```

## Build

Generate static website:
```bash
npm run build
```

Regenerate Open Graph images only (without a full Next build):
```bash
npm run build:og
```

Preview the production build locally:
```bash
npm run serve                  # serves ./out on :8080 via the `serve` package
```

## Repository Layout

```
├── content/      # Documentation MDX files (one directory per Diátaxis quadrant)
├── src/          # Next.js app and React components
├── public/       # Static assets (logos, OG images precomputed by build:og)
├── scripts/      # Link checks, doctype validation, OG generation, redirects
├── decisions/    # ADRs (architectural decision records)
└── out/          # Static export output (generated; not checked in)
```

## Architectural decisions

Substantive shape changes (information architecture, redirect strategy,
front-matter conventions) are recorded as Architecture Decision Records
under `decisions/`. The current site IA is documented in
[`decisions/0001-adopt-diataxis-ia.md`](decisions/0001-adopt-diataxis-ia.md).

## For maintainers

### Build environments

The project runs in three contexts with different submodule access:

| Environment | Clones `src/lib/docs-template`? | Result |
|---|---|---|
| Local development | Yes — via the Installation steps above. | Full per-page OG generation. |
| Sevalla deploy (`docs.pears.com`) | Yes — Sevalla is configured with an SSH deploy key with read access to `tetherto/docs-template`. Install command: `git submodule update --init --recursive && npm install`. | Full per-page OG generation. Source of truth for production builds. |
| GitHub Actions (`publish.yml`) | No — the workflow only promotes `preview → published`; it never runs `npm install` or `next build`. | Not applicable. |

> If you stand up a new build environment, give it Git read access to `tetherto/docs-template` (via SSH key) so the submodule can be checked out. Without it, `npm install` will succeed but `next build` will fail because `@tetherto/docs-seo-*` packages won't be resolvable.

### OG images

Per-page OG images are committed to `public/og/docs/` and regenerated by `npm run build:og` (which is also run automatically as the `prebuild` step of `npm run build`). Commit updated images when content changes significantly.

To skip regeneration in a build environment (e.g. for a quick preview), set `SKIP_OG_BUILD=1`. Pages will fall back to the root OG image (`public/og/docs/image.webp`).

### Bumping the `docs-template` submodule

When a new `@tetherto/docs-seo-*` release lands:

```bash
git -C src/lib/docs-template fetch origin
git -C src/lib/docs-template checkout <tagged-commit>
git add src/lib/docs-template
npm install          # regenerates package-lock.json workspace links
git add package-lock.json
git commit -m "deps: bump docs-template submodule"
```
